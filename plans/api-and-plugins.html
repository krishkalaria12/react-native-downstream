react-native-downstream · API & plugin plan

One string in, plugins for the heavy parts

The plain useChat code should take the fast streaming path. Every option moves onto the component, and code highlighting moves out of the core binary into a plugin package, as math already is.

  • Drafted 2026-10-31
  • Phase 1 0.1.x, non-breaking
  • Phases 2–3 0.2.0, one breaking release
  • Decisions all 15 resolved with the recommended option

00The change, in one picture

  • No controller to create, keep or dispose
  • Incremental parse and incomplete-Markdown preview come from a growing string
  • App-wide options set once
  • createMarkdownStream stays as an advanced option

01Why

Vercel's Streamdown and Software Mansion's react-native-streamdown both take a growing string. That matches what AI SDK's useChat gives you for each message. Ours asks for a chunk stream instead, and the obvious string code ends up on our slowest path.

  1. The string path reparses everything

    Every change to the markdown prop starts a new generation and a full parse, with no incomplete-Markdown preview. The incremental engine only helps people who adopt the controller.

    src/controlledSource.ts · src/DownstreamMarkdown.tsx

  2. Options are split across two places

    math, syntax, links, inlineHtml, cjk and allowedTags go on the controller for streams but on the view for strings. The view's math prop means something different in each case.

    src/types.ts · MarkdownStreamOptions vs MarkdownViewBaseProps

  3. The heavy highlighter is always linked

    The grammar module is 4.0 MB of generated C source in src/cpp/wasm, plus about 2.2k lines of highlighter, and every app links it. Math, 47 MB of vendor files, is already a separate package.

    Downstream.podspec · src/cpp/wasm · math/vendor

02Decisions

Each question is settled with the recommended option, highlighted. The options set aside are listed under it so the choice can be revisited later.

D1

How does text get into the view?

The source is the component's children, and the markdown prop keeps working.

  • A controller as the only way to stream
  • A render prop

It's what useChat hands you and what both reference libraries accept. Keeping markdown means no existing call site breaks.

D2

When does a string view get an incremental session?

From the first render where isAnimating is true. A view that mounts already settled keeps today's one-shot parse.

  • Always create a session
  • A separate mode="static" prop

A chat history with hundreds of settled messages shouldn't hold hundreds of native sessions. isAnimating already tells us text is arriving, so no new prop is needed.

D3

What happens when the new string doesn't extend the old one?

Call reset(next), which starts a new generation.

  • Diff the two strings and patch the document

Edits and regenerations are rare, and a reset does exactly what every update does today. Diffing is complexity with no clear benefit.

D4

Is incomplete-Markdown preview on by default?

Yes, while animating. A preview view prop overrides it.

  • Off until asked for, as today

Both reference libraries fix up incomplete Markdown by default. finish() removes the provisional styling, so settled text renders exactly what was sent.

D5

What happens to createMarkdownStream?

It stays as an advanced option and only carries text. Parse options come from the view it's bound to.

  • Remove it
  • Keep parse options on the controller

It's still the right tool for feeding chunks without re-rendering React, and for keeping a reply alive while a FlatList row is unmounted. Options then live in one place.

D6

What is the component called?

Downstream. DownstreamMarkdown stays as a deprecated alias through 0.2.x.

  • Markdown (too generic, clashes in apps)
  • Keep DownstreamMarkdown

This mirrors <Streamdown>: the package name is the component name.

D7

How are the breaking changes released?

Phases 2 and 3 ship together as 0.2.0. Old flat prop names stay as deprecated aliases that warn in development for 0.2.x.

  • Several smaller breaking releases
  • A hard cut with no aliases

One migration instead of three. Before 1.0, breaking changes are expected, and the aliases make the upgrade non-fatal.

D8

How are app-wide defaults set?

With DownstreamProvider. Props on a view win, and theme and markdownStyle merge with the provider's values first.

  • A createDownstream() factory that returns a configured component

Both props already accept arrays that merge left to right, so the provider's value just goes first. A context also lets plugins be shared across screens.

D9

What shape do plugins take?

An array of plugin objects, each with a name and optional parse, fences, tags, native and style.

  • Streamdown's fixed-key object, { code, math }

App and third-party plugins need to sit beside the official ones. With fixed keys, only plugins we already know about would fit. Array order also decides how styles merge.

D10

Where do the app's component overrides go?

components={{ fences, tags, fallback }}, with maps keyed by fence language and tag name.

  • Today's plugins.renderers and plugins.tags arrays

plugins becomes the name for feature packages, and overrides belong to the app. Streamdown uses the same components name. { chart: ChartCard } is shorter than [{ language, component }].

D11

How does math get turned on?

Through an explicit math(options) plugin. If the engine is installed but no plugin is passed, a warning appears in development.

  • Turn on automatically when the package is installed, as today

It works the same way as code(), and the delimiter options live with the plugin. The warning catches apps that would otherwise lose math without noticing.

D12

What happens to code highlighting?

It moves into react-native-downstream-code and installs through a C function-pointer hook, the same way DownstreamInstallMathEngine works. Without it, code blocks render plain.

  • Keep it built in
  • A JavaScript highlighter

It's the only heavy feature in the core. A C hook is the only thing another pod can call, and math already proves the pattern on both platforms.

D13

Where do code block layout options live?

In the core, as codeBlock={{ wrap, lineNumbers, maxHeight }}. The plugin only handles highlighting.

  • Settings on the code() plugin

Code blocks exist without the plugin, so their layout can't depend on it. This corrects the earlier suggestion to move these options into the plugin.

D14

What stays built in?

CJK, the extra syntaxes (^sup^, ~sub~, highlight, spoiler), autolinks, copy and download controls, link safety, and the fullscreen table.

  • Make CJK a plugin, as Streamdown does
  • Split the UI pieces into packages

The syntax features are parser flags that cost almost nothing. The UI pieces are about 800 lines of JS in total. Extracting them would save nothing and add setup steps.

D15

Is Mermaid part of this plan?

No. It's a follow-up plugin built on components.fences, which would prove the plugin API works for third parties.

  • Ship it alongside 0.2.0

It needs a rendering approach of its own, which would slow down the release.

03Phases

1 · Strings stream0.1.x → 2 · One place for options0.2.0 → 3 · Plugins0.2.0

The JS plugin work in phase 3 needs phase 2's plugins and components props. The native split of the highlighter (phase 3, task 3) touches only native code and can start alongside phase 2.

01Strings take the stream path

0.1.x · non-breaking

A markdown string that grows while isAnimating is true gets the same incremental parse and preview as a controller.

Tasks

  1. When isAnimating first turns true, ControlledMarkdown creates an incremental session it owns, and disposes it on unmount (D2). src/DownstreamMarkdown.tsx · src/createMarkdownStream.ts
  2. If the new string starts with the previous source, append only the added text. Otherwise reset(next) (D3).
  3. Check only the added text, against a running byte total, instead of the whole string on every update. Hold back a trailing high surrogate until its pair arrives. src/controlledSource.ts
  4. When isAnimating turns false, call finish(). If the string grows again after that, reset with the full string.
  5. Add a preview view prop, on by default while animating (D4). src/types.ts
  6. Send fence and tag renderers through the stream path's slot mechanism once a session exists, instead of the synchronous scan of the controlled source. src/fenceRenderers.ts · src/tagRenderers.ts
  7. In the README, lead "Stream a response" with the useChat string example, and move the controller under "Advanced".

Done when

  • A string grown chunk by chunk ends in the same document as the same chunks fed to createMarkdownStream. The test runs on the real engine and replays through IncrementalParser.
  • On a long response, the phone benchmark (bench.mjs, both platforms) shows per-update JS and native time for the string path within the controller path's numbers. Both are recorded.
  • A list of settled messages creates zero native sessions.
  • Preview styling is gone after finish(), and the settled output matches a one-shot parse.
  • pnpm test, test:native and typecheck pass.

02One place for options

0.2.0 · breaking, with aliases

Every option goes on the component, and app-wide defaults are set once.

Tasks

  1. Export Downstream. Keep DownstreamMarkdown as an alias that warns in development (D6). src/index.tsx
  2. Accept the source as children, and keep markdown working (D1).
  3. Make parse options view-only: math, syntax, links, inlineHtml, cjk, allowedTags, literalTagContent and disableAutolinkProtocols. createMarkdownStream drops them. The bound view creates the session with its own flags, and rebuilds it from the stored source when they change (D5). src/createMarkdownStream.ts · src/parseFlags.ts
  4. Add DownstreamProvider, a context whose defaults merge under each view's props (D8).
  5. Group the flat props into codeBlock, table, images and links. The old names stay as deprecated aliases (D7, D13).
  6. components={{ fences, tags, fallback }} replaces plugins.renderers, plugins.tags and plugins.fallbackComponent (D10).

Done when

  • Every 0.1 prop has a 0.2 equivalent or a documented removal in the migration table.
  • Each deprecated alias warns once per prop in development and behaves the same as its replacement, with a test for each.
  • Changing a parse option on a live stream view re-renders the same source under the new options without losing any text.
  • A view inside a provider with no props of its own renders the same as a view given those props directly.

03Plugins

0.2.0 · breaking

Math and code highlighting become explicit plugins, and the core binary loses the highlighter.

Tasks

  1. Add the DownstreamPlugin type and a resolver. Array order is kept, a duplicate name is a development error, and a plugin's fences, tags and styles merge under the app's components and styles (D9).
  2. Export math(options) from react-native-downstream-math. The core turns math on only when that plugin is passed, and warns in development when the engine is installed but no plugin is (D11). math/index.js · math/index.d.ts · src/parseFlags.ts
  3. Create react-native-downstream-code next to math/. It holds src/cpp/wasm and the highlighter sources, plus a podspec and an Android library. It installs through DownstreamInstallCodeHighlighter: +load on iOS, and the package resolver on Android, as math does (D12). Before moving anything, check what in src/cpp/highlight plain code blocks still need, and keep that in the core. Downstream.podspec · src/cpp/highlight · src/cpp/wasm · pnpm-workspace.yaml
  4. Remove the syntaxHighlighting prop: highlighting is on exactly when the plugin is passed. theme.syntax and syntaxColorsFromTheme stay in the core theme.
  5. Measure the core binary size before and after on iOS and Android, and add the numbers to the benchmark report.

Done when

  • The core builds and passes every test without the code package. Code blocks render plain, with copy and line numbers still working.
  • With code(), highlighted output matches 0.1 in a snapshot test.
  • With math(), math output matches 0.1, and the installed-but-unused warning fires.
  • The core's size reduction is reported in measured numbers for both platforms.

Depends on: phase 2, tasks 4–6, for the plugins and components props. Task 3 doesn't, and can start earlier.

05Risks

RiskMitigation
The startsWith check is O(n) on every update.It's a native string comparison capped at the 1 MiB source limit. Check the length first. Phase 1's benchmark gate measures it.
An update boundary splits a surrogate pair.Hold back a trailing high surrogate until the next update (phase 1, task 3), with a test that cuts between the two halves.
String users still re-render React on every token.That's the same as with any string-based library. Document AI SDK's experimental_throttle, and point at the controller for apps that need to avoid re-renders.
A FlatList unmounts a streaming row, and its session goes with it.On remount, the full string is parsed once, which is acceptable. Apps that need the session to survive use createMarkdownStream (D5).
Existing apps lose math without noticing after 0.2.0.A development warning when the engine is installed but no plugin is passed, plus a migration row (D11).
Splitting the highlighter breaks native linking on one platform.Copy the math package's exact pattern, and build the example with and without the code package in CI for both platforms.
Grouped props make 0.2.0 a large upgrade.Deprecated aliases with one-time development warnings during 0.2.x, and the migration table in the README.

06Scope

In this plan

  • String-to-stream handling and preview by default (phase 1)
  • Rename, children as source, view-only options, provider, grouped props, components (phase 2)
  • The plugin type, an explicit math(), and the react-native-downstream-code package (phase 3)
  • A migration table and size measurements

Not in this plan

  • A Mermaid or chart plugin (follow-up, D15)
  • Extracting CJK, the extra syntaxes, controls, link safety or the fullscreen table (D14)
  • Diff-and-patch for strings that don't extend the previous one (D3)
  • Removing the deprecated aliases (after 0.2.x)
  • A codemod

Based on the API comparison with vercel/streamdown and software-mansion-labs/react-native-streamdown, and on the current source of this repository.
