docs / math-and-images-plan

Typeset math and loaded images, natively

Today a formula shows its literal $$ source and an image shows only its alt text, which is what the first-release contract promised. This plan closes both rows of the Streamdown gap analysis. Math is parsed by the engine, laid out once in C++ by RaTeX (a KaTeX-compatible engine) on the worker pool, and drawn as vectors by both platforms. Images become their own segment, loaded through React Native's own image pipeline with a placeholder, a fallback and a download control, with the loaded size fed back into measurement through Fabric state.

Builds onSyntax highlighting (#15), copy and download controls (#16), theme and style (#18) and code block chrome. All are treated as merged.
Compared againstStreamdown 2.7.0 with @streamdown/math 1.0.3 (vercel/streamdown@976cf12), react-native-enriched-markdown@609971c, and RaTeX 0.1.14 (erweixin/RaTeX@776c1d3)
New dependenciesImages: none, because React Native's RCTImageLoader and Fresco are already linked. Math: RaTeX's prebuilt C ABI (MIT) and the KaTeX fonts (OFL), shipped in an opt-in package.
Decision: math is a parse feature plus a laid-out display list; images are a segment whose size arrives through state

The parser recognizes math and turns it into a MathBlock block or a Math inline run. A post-parse pass, shaped like the highlighting pass, sends each formula through RaTeX's C ABI and stores the result on the document as an em-unit display list (glyphs, rules and paths). The layout does not depend on theme, font scale or width, so it is computed once, shared by measurement and drawing, and reused across snapshots. Both platforms draw the same list with the KaTeX fonts, so a formula is the same on iOS and Android and as close to Streamdown's KaTeX output as RaTeX's support table allows.

An image-only paragraph becomes an Image block in its own segment. Its box is decided by one C++ function from its state: pending, loading, loaded with a known size, failed, or blocked. A load that finishes records the size in a process-wide size cache and sends a Fabric state update, so the shadow node measures again with no React render. A recycled message is laid out at its final size on the first frame.

What makes RaTeX fit this engine in particular: its output is data, not a view. Constraints from the contract and the code

Rules from api.md, the feature matrix and earlier items that both tracks must keep.

  • Plain prose does not pay. A document without math or images loads no RaTeX, reads no font, creates no image view, and allocates nothing in the new passes. The math pass returns the same handle when there is nothing to lay out, as highlightCodeBlocks does.
  • Unsupported syntax is literal, never executed. A formula that fails, or any formula when the math package is absent, shows its source exactly as written, delimiters included. That is today's display, so turning math off is a no-op for existing users.
  • Measured height equals drawn height. Math sizes are in the document. Image sizes and states travel in LayoutHint and the Fabric state, as CodeLayout does, and one function decides an image box.
  • No React render for content work. An image finishing loading updates Fabric state, as expand does.
  • Copy is what the reader sees, as text. Copying a typeset formula yields its source with its delimiters, as KaTeX's copy-tex extension does, so a paste into another Markdown editor reproduces it.
  • The settled document is a parse of the canonical source. No math repair survives finish(), and source ranges are never touched.
  • Identities name content. sameBlock (Compare.cpp:5) must compare the new math and image fields, or the committed-segment cache draws stale content, the same trap the chrome plan found with info.
  • md4c is pinned unmodified. engine.test.mjs checks SHA-256 digests, and the vendored README says a local edit must be "a deliberate patch, recorded on purpose". The fence patch is recorded that way.
  • Untrusted input. Formulas and URLs come from model output. Size caps, URL validation and the prefix list apply before anything reaches RaTeX or the network.

1. Recognizing math in the parser

md4c 0.6 already reports MD_SPAN_LATEXMATH and MD_SPAN_LATEXMATH_DISPLAY when MD_FLAG_LATEXMATHSPANS is set (md4c.c:3632 collects runs of one or two $; an opener must follow whitespace, punctuation or a line start, and a closer must precede one). That covers inline math. Three things are missing, and each is solved at the narrowest layer:

  • Block math across lines (md4c patch). $$ alone on a line is recognized only as a span, so a blank line, a line starting - , a | or four spaces of indentation inside an aligned environment breaks the formula into Markdown. The patch adds MD_FLAG_LATEXMATHBLOCKS: in md_is_opening_code_fence and md_is_closing_code_fence (md4c.c:6045, :6075), a line that is exactly $$ after up to three spaces, with only whitespace after it, opens or closes a fence, reported as MD_BLOCK_CODE with fence_char = '$'. Containers, lazy continuation and an unclosed fence running to the end all come from md4c's existing fence machinery. This is the change upstream issue #270 asks for, so the patch is offered upstream.
  • Single dollars off (same patch). md4c has no switch between $ and $$. MD_FLAG_LATEXMATHNOSINGLE skips a one-dollar run in the same collector, two lines. Without it, $5 – $10-shaped text could pair, and a literal fallback would then lose the emphasis md4c skipped inside the span.
  • Brackets (no md4c change). A pre-scan in MathScan.{h,cpp}, beside Scan.h, finds paired, unescaped \(…\) and \[…\] outside code fences and rewrites each two-byte delimiter to $$ in a copy of the source. The copy has the same length, so every md4c offset still points at the same byte of the canonical source. The builder reads text bytes from the original at the same offset, so code, link text and an unpaired delimiter show exactly what was written. A \[ alone on a line becomes a $$ line and so a fence. The builder knows which delimiter it saw from the original bytes, which is how \( stays inline although md4c reports a two-dollar span.

The parser turns all of this on only when a math option asks for it (see Public API). With math off, the flags are off and parsing is byte-for-byte today's.

2. The document model

// Document.h
enum class BlockKind : uint8_t { …, TableRow = 5, MathBlock = 6, Image = 7 };

/// One formula. Inline math covers its literal text in Block::text, delimiters
/// included, so a fallback, a copy and today's rendering are the same string.
struct MathSpan {
  uint32_t start{0}, end{0};        // UTF-16 into Block::text, the literal with delimiters
  std::string tex;                  // between the delimiters, UTF-8, newlines as written
  bool display{false};              // display style: blocks, \[…\], and a promoted lone $$…$$
  MathDelimiter delimiter{MathDelimiter::DoubleDollar};
  MathLayout::Handle layout;        // null until laid out, or when it failed
  std::string error;                // RaTeX's message when it failed; empty otherwise
  bool operator==(const MathSpan &) const;   // compares start, end, tex, display, delimiter
};

struct Block {
  …
  /// Paragraph, heading, table row: the inline formulas, sorted by start.
  /// MathBlock: exactly one, display, covering the whole text.
  std::vector<MathSpan> math;
};
  • A MathBlock's text is the TeX between its fences, as a code block's is its code, so selection and copy return the formula. A ```math fence becomes a MathBlock with MathDelimiter::MathFence.
  • A paragraph that is one display span ($$…$$ or \[…\] on one line, with nothing else but whitespace) is promoted in finishLeaf to a MathBlock, the way Streamdown unwraps an image-only paragraph.
  • Inline math is a run, not a placeholder. Block::text keeps the literal, so every offset, link range and table cell boundary is unchanged, and the platform decides at draw time whether the run is typeset or literal.
  • Size caps. A formula over 4 KiB of TeX, or a document with more than 512 formulas, keeps the rest literal and never calls RaTeX. RaTeX already stops at 1,000 macro expansions and has its own recursion guard. The caps bound the cost of hostile input before it reaches a library that aborts on panic.
  • sameBlock compares math without its layout, so a block keeps its identity while its layout is filled in.

3. The math engine seam

// src/cpp/math/MathEngine.h
/// A display list in em units, decoded once from RaTeX's JSON. Immutable and shared.
struct MathLayout {
  using Handle = std::shared_ptr<const MathLayout>;
  float width{0}, height{0}, depth{0};          // em; the baseline is at y = height
  struct Glyph { float x, y, scale; MathFont font; char32_t codePoint; uint32_t color; };
  struct Rule  { float x, y, width, height; uint32_t color; bool dashed; };   // Line and Rect
  struct Path  { float x, y; std::vector<PathOp> ops; bool fill; uint32_t color; };
  std::vector<Glyph> glyphs; std::vector<Rule> rules; std::vector<Path> paths;
};
/// 0 means "the surrounding text color", so dark mode, a theme and increased
/// contrast reach a formula without laying it out again. \color{…} keeps its own.
inline constexpr uint32_t kInheritColor = 0;

enum class MathFont : uint8_t { MainRegular, MainBold, MainItalic, MainBoldItalic, MathItalic, MathBoldItalic,
  AMSRegular, CaligraphicRegular, CaligraphicBold, FrakturRegular, FrakturBold, SansSerifRegular, SansSerifBold,
  SansSerifItalic, ScriptRegular, TypewriterRegular, Size1, Size2, Size3, Size4, System /* "CJK-Regular" */ };

struct MathEngineFunctions {        // RaTeX's C ABI, as function pointers
  RatexResult (*parseAndLayout)(const char *, const RatexOptions *);
  void (*free)(char *);
  const char *(*lastError)(void);
};
namespace MathEngine {
  void install(const MathEngineFunctions &);   // iOS: from the math pod; Android: dlopen
  bool available();
  /// Lays out one formula through the shared cache. Never throws.
  MathLayout::Handle layout(std::string_view tex, bool display, std::string *error);
}
  • Inherited color. RaTeX colors every item it does not override with the default color in RatexOptions. The engine passes a sentinel ({0, 0, 0, 0}) and the decoder maps exactly that value to kInheritColor, so the layout does not depend on the theme and the platform draws in the run's own dynamic color.
  • The decoder (MathDisplayList.cpp) is a small JSON reader for this one schema. It ignores unknown fields and item types, as the protocol requires, treats a missing version as 0, limits nesting and item counts, and rejects a list with non-finite numbers or a width over 2,000 em. A rejected list is a failed formula, never a crash.
  • The cache keys on the TeX and the display flag, holds about 2,000 entries (an LRU bounded by item count), and is shared by sessions and controlled documents, so a full-mode reparse or a recycled message never calls RaTeX again for a formula it has seen.
  • Not installed. available() is false and every formula keeps its literal. A development warning fires once per process, and only when a document actually contains math.

4. The math pass

src/cpp/math/MathBlocks.{h,cpp} mirrors CodeBlocks.h: layoutMath(DocumentHandle, previous) runs after the parse wherever highlighting runs (PreparedDocument.cpp and IncrementalParser.cpp), fills MathSpan::layout for the tail's blocks, and returns the same handle when the tail has no MathSpan. Committed blocks keep their layouts in the shared prefix. Layout cannot depend on the theme, font scale or width, so this pass never re-runs for a theme change, a rotation or Dynamic Type.

Last good layout. A formula whose block is not settled and that fails to lay out keeps the layout of the same span in the previous snapshot, when that span's TeX is a prefix of the new TeX. While \frac{a}{ streams in, the reader keeps seeing the last prefix that laid out rather than a formula that flickers to red source on every token. Before anything has laid out, the span shows its literal in the run's normal color. Error color and onMathError apply only once the block is settled.

5. Sizing and drawing

  • Font size. Inline math is the surrounding run's size times 1.21, KaTeX's own .katex { font-size: 1.21em }, so a formula in a heading is a heading-sized formula. Block math uses math.fontSize, which defaults to the paragraph size times 1.21. Both are multiplied by the font scale like text.
  • One height rule. mathBlockHeight(layout, fontSize, padding) = (height + depth) · fontSize + 2 · padding in MathLayout.h, called by both platforms' segment height functions.
  • Fonts. The 20 KaTeX TTFs (about 540 KB) ship in the math package. Each is loaded on first use from its own file: CGFontCreateWithDataProvider plus CTFontCreateWithGraphicsFont on iOS, so nothing is registered process-wide, and Typeface.createFromAsset on Android. System glyphs (CJK, emoji) use the platform font.
  • Drawing. A glyph draws at (x, y) · size scaled by scale; a rule is a filled rect, dashed when asked; a path is a CGPath or android.graphics.Path. Vectors at draw time, so a formula is sharp at any zoom and in any appearance.
  • Direction. A formula is always laid out left to right, as KaTeX does, inside text of either direction. A block is centered by default (math.textAlign).
  • Too wide. A block wider than the column scrolls sideways inside its segment, reusing the code card's horizontal scroll and drag rules. An inline formula wider than the line is scaled down to the line, but never below 0.5; past that it overflows and is clipped at the segment edge.

6. Speech, copy and export

  • Spoken math. MathSpeech.cpp turns TeX into a sentence from a table, not a TeX engine: Greek letters, operators and relations, \frac{a}{b} as "a over b", ^2 and ^3 as "squared" and "cubed", other superscripts as "to the power", subscripts, \sqrt, \sum, \int and \lim with their limits, and a matrix as its size. An unknown command is spoken as its name without the backslash. VoiceOver reads "math, x equals negative b plus or minus …"; TalkBack the same through contentDescription. The source is the fallback, and it stays reachable with the rotor's character navigation in the inline case.
  • Copy. A selection copies Block::text, which is the literal with delimiters for inline math and the TeX for a block. iOS swaps each attachment back for its literal in the existing copy: override (DSSegmentViews.mm:209). Android keeps the literal characters under a ReplacementSpan, so the platform copies it unchanged.
  • Export. A table copied as Markdown, CSV or HTML writes a cell's math as its literal source. No math copy button: Streamdown has none, and selection covers it.

1. Images in the document

  • Recording. enterSpan(MD_SPAN_IMG) (MarkdownParser.cpp:281) reads MD_SPAN_IMG_DETAIL::src and title, which the builder ignores today, and closeLinkOrImage fills the range it already computes. Every image is recorded, loadable or not, so a run's alt text can name its image.
  • Promotion. In finishLeaf, a paragraph whose runs are all ImageAlt (or a link wrapping one image), separated only by whitespace and soft breaks, becomes a BlockKind::Image block listing its images. Its text is the alt texts joined by newlines, so accessibility, export and a fallback read the same string. Anything else in the paragraph keeps it a paragraph with alt text, as today.
  • URL policy. isLoadableImageUrl sits beside isActionableUrl in LinkPolicy.cpp: HTTPS only, case-insensitive scheme, a host, no control characters or spaces. The prefix list is a view prop, so it is applied in the box rule below rather than in the parse, and the document stays the same whatever the prop says.
  • Download name. imageDownloadName(url, alt, mime, configuredBase) in Export.cpp ports Streamdown's rules (URL extension up to four characters, else the MIME type's, else png; the alt text without its extension as the base, else image) through the same sanitizer as code names.
  • Identity. sameBlock compares images and the image records they name, by URL and alt text.
  • Segments. planSegments gives an Image block its own SegmentKind::Image segment, with an imageOrdinal counted like codeOrdinal, and a MathBlock its own SegmentKind::Math. A committed chunk ends before either, as it does before code.

  bool enabled{true};             // the `images` prop
  std::vector<ImageEntry> entries;       // sorted by ordinal
  bool operator==(const ImageLayout &) const = default;
};
/// The box one image takes in a column, from its state and the theme's image metrics.
/// The only place an image's height is decided; both platforms and the shadow node call it.
Size imageBox(const ImageEntry *, float columnWidth, const ImageMetrics &, float fontScale, float fallbackTextHeight);
  • Pending and Loading with no known size: the placeholder's 192×96 points, clamped to the column. Loaded: pixelWidth × pixelHeight in points, scaled down to the column width and to image.maxHeight (0, the default, means no cap), never scaled up. Failed, Blocked, Disabled: one line of fallback text, so a broken image takes the room of its alt text and not of a placeholder.
  • Sizes outlive views. ImageSizeCache, a process-wide LRU of 1,024 URLs, keeps each URL's pixel size or its failure. The shadow node builds ImageLayout from it at measurement, so a message scrolled back into view, or a second message showing the same chart, lays out at its final size on the first frame and never jumps.
  • The size comes back through state. When a load finishes, the platform records the result in ImageSizeCache and dispatches a state update on the view's family, the way relayoutWhenPrepared does (DownstreamMarkdownShadowNode.cpp). The clone's layout() finds a different ImageLayout, measures again and commits a new state, with no React render. The measure cache (DownstreamTextLayoutManager.h) keys on ImageLayout as it does on CodeLayout.
  • Load events are batched. Loads that finish within one frame produce one state update per view, so a message with six images relays out once rather than six times.

3. Loading

  • React Native's own pipeline. On iOS, RCTImageLoader from the context container under the "RCTImageLoader" key. Bridgeless mode inserts it there (RCTInstance.mm:414), and React Native's own ImageManager.mm reads it the same way. On Android, Fresco's ImagePipeline; React Native 0.83 ships Fresco 3.6.0. Apps keep their own HTTP stack, cookies, disk cache and custom URL handlers, and no image library is added.
  • The contract's four requests. One DSImageLoader on iOS and one ImageLoader on Android per process: at most four requests in flight, requests for the same URL deduplicated, and each request reference-counted by the image views that want it. It is cancelled when the last one is recycled, its generation is reset, or its URL leaves the document.
  • Decoded to the size drawn. A request asks for the column width times the screen scale (RCTImageLoader's size-aware load; Fresco's ResizeOptions), so a 4,000-pixel photo costs a phone-sized bitmap. GIFs show their first frame. SVG is not decoded by either pipeline and falls back.
  • When a request starts. As soon as a snapshot holds a complete, loadable URL that the prefix list allows, settled or not, as Streamdown loads as soon as an <img> renders. A partial destination is never requested: it is either literal text or, with preview, an empty one.
  • Privacy. Every request is to a URL a model wrote. allowedImagePrefixes is the switch for apps whose models read untrusted content; see the open question on its default.

4. The image view

  • One view per image block (DSImageSegmentView, ImageSegmentView), holding an image view per image, the placeholder, the fallback label and the download button. Container bars and markers are drawn from the block's containers, as the table segment does.
  • Press. A linked image reaches onLinkPress with the link's range. Any other loaded image reaches onImagePress, so an app can open its own viewer. The library opens nothing.
  • Download. A bottom-trailing button once the image is loaded, as in Streamdown. It writes the loader's cached bytes to a file and presents the save dialog the code download already uses (DSFileExporter, DocumentExporter.kt). Saving to Photos would need a permission, so it is not offered.
  • Accessibility. One element per image: the image trait (iOS) or role (Android), the alt text as the label, or translations.image ("Image") when there is none, and the state when it is not loaded ("loading", "not available", "blocked"). A linked image is a link element.

Packaging the math engine

Installing a package is the opt-in, as @streamdown/math is, and the binary never reaches apps that do not want it.

  • react-native-downstream-math, a second workspace package in this repository (math/), autolinked. It has no JavaScript API beyond being installed.
  • iOS. Its podspec depends on Downstream and vendors RaTeX's static XCFramework and the KaTeX fonts as a resource bundle. The XCFramework is fetched at prepack time from the pinned release (v0.1.14, sha256-verified, from a ratex-version.json like enriched-markdown's) and shipped inside the npm tarball. No postinstall download, so pnpm, --ignore-scripts and offline installs work. That was enriched-markdown's #745. Only the iOS device and simulator slices are kept.
  • Android. Its build.gradle adds implementation("io.github.erweixin:ratex-android:0.1.14") from Maven Central. No binary in the tarball. The core library finds the library at runtime, so the core never links against it.
  • Size. The Android library is 3.1 MB uncompressed on arm64 and 1.2 MB compressed, per ABI. enriched-markdown documents 3–5 MB on iOS. Fonts add 540 KB. Phase B5 measures the example app's release builds with and without the package and records the numbers in the README.
  • Licenses. RaTeX is MIT; the KaTeX fonts are SIL OFL 1.1 and their notice ships with the package (licenses/), as RaTeX's own third-party notice asks.
  • Next to enriched-markdown. An app with both libraries resolves one ratex-android through Gradle. On iOS both pods link the same static archive, and the linker loads each archive member once. The C ABI is the only surface, and the JSON carries a version, so a mismatch degrades to the decoder's tolerance. A Phase B5 check builds the example with both installed.

Risks and open questions

The three defaults are decided; the rest are risks and open questions with their mitigation.

Question or riskRecommendation
Default of images
decided		On, for Streamdown parity and because the contract already planned HTTPS images. The cost is that apps upgrading start making network requests from model output, and markdown-image exfiltration is a known prompt-injection channel (EchoLeak and others). Say so in the release notes and the README, and document allowedImagePrefixes as the defense.
Default of allowedImagePrefixes
decided		['*'], rehype-harden's and Streamdown's default. An app that feeds tool output, web pages or email into its model should pass its own CDN prefixes. A stricter default would break every image the moment the feature ships.
Brackets on by default
decided		On. They are the most common math form from OpenAI-family models and Streamdown's most-filed math issue. \(…\) in prose meaning literal parentheses is rare, and math={{ brackets: false }} restores it.
RaTeX aborts on panicIts release profile sets panic = "abort", so a parser bug kills the app. Mitigations: the size caps and nesting checks before the call, the hostile corpus on every version bump, and a pinned version. If a crash is ever seen, build our own artifact from RaTeX's source with panic = "unwind" and a catch_unwind wrapper. That puts Rust in our release pipeline, never in an app's build.
Pre-1.0 display listThe JSON protocol may change before 1.0. The pin, the version field and a tolerant decoder cover it, and a bump is a deliberate pull request with the layout goldens.
KaTeX gaps in RaTeXRaTeX's support table scores some formulas below 1.0 on ink comparison, and it has no \includegraphics or HTML extensions. Anything it rejects shows its source, as KaTeX's throwOnError: false does.
md4c patch upkeepSmall (the fence check and one flag), recorded in the README and pinned. It is the change upstream #270 asks for, so the goal is to drop it once upstream merges.
A stray $$ lineAn unclosed fence runs to the end of its container, as remark-math's does, so a model that writes a lone $$ in prose turns the rest into math. That is parity, and the literal fallback keeps it readable.
Layout jump on image loadUnavoidable on first load, as on the web. The size cache removes it for every later view, and load batching keeps it to one relayout per message. Keeping a chat list anchored is the list's job (maintainVisibleContentPosition).
Image memoryDecoding at display size, Fresco's and RCTImageLoader's caches, and releasing references when recycled. Bench covers a 50-image history.
Fresco not initializedInitialize with React Native's default config when Fresco.hasBeenInitialized() is false, so an app that sets its own config keeps it.
Inline math line heightA tall fraction grows its line, as KaTeX's does on the web. That is correct but changes rhythm. The scale-to-fit floor keeps a long formula from overflowing badly.
BudgetsProposed, measured in Bench: the math pass under 2 ms per streaming snapshot with a cached prefix; a 100-formula answer laid out under 50 ms on the worker on a mid-range Android; zero RaTeX calls for a prose-only document.
Open: inline imagesAlt text for now. Badges and emoji images are rare in chat. The math attachment path is reusable when they matter.
Open: image long-press menuA context menu (copy image, save, share) would be more native than a button. Ship Streamdown's button first; add the menu if adopters ask, because it competes with the app's own long-press menu.
Open: request headersenriched-markdown has imageRequestHeaders. React Native's loaders already apply the app's own interceptors and cookies, which covers most signed or authenticated URLs. Leave it out until someone needs per-view headers.
