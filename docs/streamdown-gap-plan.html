What the research changed

Corrections to the gap analysis. Each one moves a row's size or its design.

The analysis says What is true Consequence for the plan
disableAutolinkProtocols needs a dialect change It does not. The builder already holds a bare URL until its first text offset is known, at MarkdownParser.cpp:1316, and decides there whether it becomes a link. A protocol check at that point, behind three parse bits. It also covers <a@b.com>, which dropping md4c's permissive flags would not.
CJK autolinks run past 。，） md4c rejects them outright. Its permissive autolink needs whitespace or ({[ before and )}].!?,; or whitespace after, and its hostname and path scan stops at the first non-ASCII character. A worse failure than Streamdown's: the URL is not a link at all. The fix is a boundary patch in md4c, not a post-pass.
**太字**。 probably fails It renders bold. The failures are a delimiter between CJK punctuation and a CJK letter, and ~~ next to any letter. The fixtures below replace the guess, and they are the acceptance list for phase 3.
Line marks are a gap Streamdown forwards the meta string and draws nothing with it. Its remarkCodeMeta only feeds startLine. Drawing marks puts Downstream ahead. It moves to polish.
The HTML gap is details, summary, kbd, mark Streamdown's sanitizer is GitHub's schema: it renders details, summary, kbd, b, i, s, ins, a and more, unwraps every other tag to its text, and drops comments. mark is not in the schema, so it is unwrapped. Two gaps the analysis missed: comments render as visible text, and unknown-but-real HTML tags show as source. mark support would be ahead of Streamdown.
Link policy: add tel: and relative URLs Streamdown's defaults also allow irc:, ircs:, xmpp:, path-relative URLs (/, ./, ../) and #fragments without any defaultOrigin. A bare docs/a is shown as text with a [blocked] suffix. Relative links become an opt-in parse bit, resolved in JavaScript, with the raw href kept on the event.
Table full screen Streamdown disables the button for the whole stream (disabled={isAnimating}) and gives the full screen view a sticky header; the inline view has none. Downstream enables it per settled table, as its other controls already are, and pins the header in both views.

Ground rules for every phase

These come from how the engine is already built, so a new feature fits the shape the existing ones have.

Where a setting lives

  • Which runs exist (a link, a style, a tag) is a parse option: a ParseFlags bit or a field of ParseOptions. A stream reads it once in createMarkdownStream, because parse options are part of a source's identity.
  • Anything that changes a height joins LayoutHint, as CodeLayout does, so the worker, the shadow node and the view measure the same layout.
  • Everything else is a view prop, resolved in JavaScript where possible, the way controls is.

How it is built and proved

  • C++ decides; Kotlin mirrors it, as CodeLayout.kt mirrors codeCardHeight, with a host check in tests/android.
  • Positional arrays only grow at the end: CONTROL_LABEL_KEYS and the control bitmask, whose codegen default (127) moves with each new bit.
  • Tests use the real engine: dump_document cases in engine.test.mjs, test_incremental for anything that can move a commit boundary, vitest through real-engine-module. Fabric and JNI changes get a device run on both platforms, and pnpm test:ios:layout runs when src/ios changes.
  • Each md4c change is a LOCAL PATCH behind a flag that is off by default, recorded in src/cpp/md4c/README.md, pinned in engine.test.mjs, and offered upstream.

The rule the feature set was built on still holds: plain prose stays independent of the heavier paths. Nothing here adds a dependency to the core package. Mermaid, if it happens, is a separate package like math.

Recommended order

Parser-only work first, because it is low risk and unblocks the fixtures. The two phases that touch Fabric state and JNI come after. Each numbered item is about one pull request.

  1. SFailing fixturesThe probe table as engine tests, so each phase turns its own rows green.
  2. S–MLinkstel:, relative links, autolink protocols, link safety. Parser and JavaScript only.
  3. LTable max height, expand, full screenThe one block left without a way out of a nested scroll. Touches layout, state and both platforms.
  4. MCJK emphasis and autolink boundariesTwo md4c patches and a parse bit.
  5. LHTML subset v2A tag table, hidden comments, new inline styles, allowedTags.
  6. XLDetails and block custom tagsA new container kind and a reader choice. The largest single item.
  7. S–MPolishLine marks, engine-decided direction, icons, translations.
  8. opt-inMermaidAn example renderer now; a package only after a spike.
  9. backlogBeyond parityFeatures enriched-markdown has that neither list covers.

0Failing fixtures

Size S. No behaviour change.

Add every row of the probe table to engine.test.mjs as a dump_document case with its expected render model, marked as a known failure. A later phase removes the mark from the rows it fixes. The rows that already work stay as regression cases.

  • CJK emphasis, strikethrough and autolink cases, with the expected runs and links.
  • Link scheme cases: tel:, relative, fragment, bare docs/a, javascript:.
  • HTML cases: inline comment, comment block, an unclosed <!--, details in both forms, each phrasing tag, Array<string>.
  • A test_incremental case that streams a details block a byte at a time, so phase 5 has a commit test to pass.

1Links

Size S–M. Covers Link safety, Wider link policy and disableAutolinkProtocols.

Item Design Files Proof
1.1 tel: Accept tel: followed by + or a digit in isActionableUrl. On by default, as in Streamdown. Optionally irc:, ircs: and xmpp: for parity. LinkPolicy.cpp, contract docs in types.ts Engine cases; a vitest press through the real engine
1.2 Relative and fragment links A parse bit LinkRelative, set by links={{ relative: true }} or a defaultOrigin. It accepts /…, ./…, ../… and #…, as rehype-harden does, and never javascript:, data:, file: or vbscript:. The press event keeps the source as href and resolves url against defaultOrigin in JavaScript. MarkdownParser.h (bit), LinkPolicy.cpp, parseFlags.ts, DownstreamMarkdown.tsx Resolver unit tests, including ../ and query strings. Do not rely on React Native's URL polyfill to resolve against a base
1.3 disableAutolinkProtocols Three parse bits: no mailto, no http (which www. produces), no https. The builder skips the link at the point it already decides one. Strings are normalized as Streamdown does: trimmed, lower case, colon optional. The text is unchanged; only the link goes. MarkdownParser.cpp (around line 1316), parseFlags.ts, types.ts, createMarkdownStream.ts Bare, angle and www. forms; an explicit [x](mailto:…) stays a link
1.4 linkSafety JavaScript only. With no onLinkPress, the view opens links itself: onLinkCheck(url) true opens through Linking; otherwise renderModal, or a native Alert with Open, Copy link and Cancel. With onLinkPress, behaviour is unchanged, and an exported openLinkSafely() lets the app use the same flow. Copy needs a copyText method on the TurboModule, since React Native core has no clipboard. DownstreamMarkdown.tsx, a new linkSafety.ts, NativeDownstreamSession.ts, controls.ts (labels) Vitest for each path. Labels: openExternalLink, externalLinkWarning, close, copyLink, openLink

DecidedThe view opens links itself when the app passes no onLinkPress, behind link safety, which is on by default. Today such a press does nothing, so this changes what existing apps do and goes in the changelog.

3CJK

Size M. Two md4c patches. The fixtures decide when it is done.

Item Design Files Proof
3.1 CJK-friendly emphasis MD_FLAG_CJKFRIENDLY implements the markdown-cjk-friendly amendment for * and _, and for ~~ as remark-cjk-friendly-gfm-strikethrough does. Compute left-flanking and right-flanking the cmark way, then map them to md4c's opener and closer flags. The CJK test is comrak's range table (Unicode 18, about 70 ranges), with its handling of variation selectors that follow a CJK character. md4c.c around lines 3305 and 3614, md4c.h, the md4c README The fixtures, and the spec's own cases if their licence allows
3.2 Autolink boundaries In md_analyze_permissive_autolink, accept a CJK character or CJK punctuation immediately before the start and after the end. The result is the split Streamdown's plugin produces. md4c.c around line 4420 The three failing autolink rows
3.3 Option A parse bit Cjk, a cjk prop and a stream option. On by default; cjk: false turns it off. MarkdownParser.*, parseFlags.ts, types.ts Vitest for resolution
3.4 Preview The streaming repair in remend/Preview.cpp tests flanking itself. It should use the same rule, so **太字 previews. A mismatch only loses that repair, because every repair is proved by reparsing. Preview.cpp, Scan.cpp test_preview
  • Differential test: the whole engine and remend corpora produce identical render models with the bit on and off. This is what justifies turning it on by default.
  • Bench: the CJK lookup runs only when neither neighbour is whitespace, as the spec's implementer notes suggest.
  • Both patches offered to md4c upstream, as the $$ fence patch was.

4HTML subset v2

Size L. Replaces the three-tag allowlist with a table, and closes the two gaps the analysis missed.

4.1 The tag table

InlineTag in Scan.cpp becomes a sorted table from tag name to action. Name matching is generalized to letters, digits and hyphens, so custom tags can be named.

Action Tags Notes
Existing style b strong · i em · s del strike · code samp tt · sub sup br Reuse the current InlineStyle bits
New style kbd · mark · u ins Bits Keyboard, Highlight, Underline, each with theme slots from the slot generator and drawing on both platforms. kbd draws as a key cap, like inline code with a border
Link a href A small attribute parser (quoted and unquoted values, entities). The URL goes through the same policy as a Markdown link
Unwrap span font abbr small q time The tag is hidden and its text kept, as Streamdown does
Hide Comments, inline and as a block A comment block emits no block. An unclosed <!-- stays text, so one stray opener cannot hide the rest of a stream
Drop with content script style iframe object embed template Never shown, not even as source
Literal Every name that is not an HTML element A deliberate difference from Streamdown: Array<string> and <T> keep their text

The htmlTags preview, which hides a half-arrived tag at the stream tail, reads the same table through a generalized isInlineTagPrefix. The bench:inline-html bench guards the lookup cost.

4.2 allowedTags and literalTagContent

  • Streamdown's shape, Record<tag, attributes[]>. ParseOptions gains a tag policy compared by value, and the native prop carries it as strings.
  • Document gains a tags list (name, the allowed attributes, source range). InlineRun gains a tag index beside link.
  • markdownStyle.tags[name] styles a custom tag, as enriched-markdown's linkVariants styles a link. onTagPress({ tag, attributes, text, range }) reports a press.
  • literalTagContent replaces a tag's content with the raw source between its open and close tags, when both are in one block.

4.3 normalizeHtmlIndentation

A rewrite that keeps the source the same length: the indentation moves to after the tag instead of being removed. It runs where the math delimiter rewrite runs, and only when the document starts with a tag (Streamdown's rule), so every offset outside the tag is unchanged.

5Details and block custom tags

Size XL. A new container kind that spans several md4c blocks, and the first collapsible content in the engine.

5.1 <details> and <summary>

  • ContainerKind::Details, holding the open attribute. The summary is a synthetic first block, as an admonition's title is.
  • The builder pairs opening and closing HTML blocks with a stack, so nesting works. A closing tag with no opener is hidden.
  • The one-block form, with no blank lines, is split: the summary from the tag, and the body parsed as Markdown. That goes past GitHub and Streamdown, which show the body as raw text.
  • Streaming is already safe: provesClosed refuses a commit while the last block is inside a container, so a details block commits in one piece after </details>. The phase 0 incremental test proves it.
  • Open or closed is a reader choice, like code expand. Fold the code choices, the table choices and this one into one ReaderChoices in LayoutHint, and route it through state and JNI once.
  • A closed body lays out at zero height. The segment plan does not change, because it is cached per committed chunk.
  • The summary is a button with an expanded state for screen readers. Copy and export include the hidden body.

5.2 Block custom tags

A multi-line allowed tag becomes the same kind of container, with a tag index. plugins.tags[name] draws it through the fence slot hosting that renderers already use (HostLayout), and receives the inner Markdown and isIncomplete. fallbackComponent is the component for an allowed tag with none of its own; with neither, the children render natively.

RiskA very long details block holds every commit until it closes, so it can reach the tail limit and fall back to full parses. The existing TailLimit fallback covers correctness; the bench should measure the cost.

7Mermaid

The analysis is right that it does not belong in core. Decided: an example renderer now, and a native package only if a spike shows the cost is worth it.

Option What it is Cost
A · Example renderer chosen A plugins.renderers component in the example app that draws with mermaid.js in a WebView, with pan, zoom, full screen and export. Small, and adds no dependency to any published package
B · Native package later spike react-native-downstream-mermaid, vendoring a Rust renderer through the pinned, checksum-checked pipeline RaTeX uses. mermaid-rs-renderer (MIT, 23 diagram types) has a vector scene output that could be drawn natively as math is; sebastian (MIT) claims SVG identical to mermaid.js for 18 types. Large. Neither has a C interface, so a bridge crate is ours to write. Measure binary size and output quality before deciding
C · Documentation only not chosen The status quo: describe the renderer path. None

8Beyond parity

Backlog from react-native-enriched-markdown. None of it is in the gap analysis.

  • onLinkLongPress, and control over the iOS link preview.
  • Task item press events.
  • md4c's own ==highlight==, __underline__ and ||spoiler|| syntaxes. The first two reuse the phase 4 style bits; spoilers need tap to reveal.
  • linkVariants, per-URL link styles, which pair with app-defined link schemes.
  • Extra items in the text selection menu, and copy as Markdown.
  • A streaming mode that hides a table until it is complete.

Decisions

Settled on 2026-10-06, each as recommended. Each changes what an existing app sees, so each goes in the changelog when its phase ships.

Question Decided Why
tableMaxHeight default 300, with an expand control Matches Streamdown and the code block's 400 precedent. 0 avoids a nested scroll but differs from Streamdown
Open links with no onLinkPress Yes, with link safety on Today such a press does nothing, which no reader expects
CJK parsing default On, with cjk: false to opt out The differential test shows non-CJK text is unchanged
Unknown HTML tags Unwrap real element names; keep other names literal Streamdown's reading for HTML, without eating generics in prose
Details body without blank lines Parse it as Markdown Models write details without blank lines
Table full screen A JavaScript modal holding a second view No new native drawing, and the app can replace it
Mermaid Example renderer now, Rust spike later Keeps core free of a diagram engine until the cost is known
