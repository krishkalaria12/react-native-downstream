What Streamdown has that Downstream does not

A feature-by-feature comparison against Vercel's Streamdown, the web renderer this project is benchmarked against. It lists what is still missing from the native renderer, how each gap relates to the API contract, and a suggested order for closing them.

Compared againstStreamdown 2.6.0, vercel/streamdown@455d32e, with its @streamdown/code, math, mermaid and cjk plugins
Out of this listIncomplete-Markdown repair. The remend port lands separately and is treated as done here.

High impact for AI chat

The gaps a user of a chat app would notice first when switching from Streamdown.

Streamdown featureDownstream todayNotes
Syntax highlighting
shipped		 Colored native code, on by default, with syntaxHighlighting={'{false}'} to turn it off Shipped in the syntax highlighting plan: vendored Lexilla lexers in src/cpp/lexilla/ tokenize on the shared worker pool, iOS and Android read one GitHub-themed palette, and the 64 KiB cap and no-auto-detect rule are kept. Fidelity is Notepad++-like rather than Shiki's: a per-line post-pass promotes a call, a property, and a PascalCase type, and JSX tags are the weakest case.
Code block header, line numbers, max height
not planned		 None Language label, lineNumbers, startLine= read from the fence meta string, codeBlockMaxHeight (default 400) that keeps scrolling to the bottom while the block streams, and a placeholder while highlighting loads. The meta string is dropped today: only the language is kept at MarkdownParser.cpp:177.
Copy and download controls
planned		 Whole-document copy via getSource() controls.code (copy, download), controls.table (copy as CSV, TSV or Markdown, download, csvSeparator) and controls.image. Tables need a way to extract their data, like Streamdown's tableDataToCSV, tableDataToMarkdown and tableDataToTSV. See the copy and download controls plan.
Math
planned		 Literal delimiters and source @streamdown/math uses remark-math and KaTeX, with an opt-in for single-dollar inline math. md4c already has MD_FLAG_LATEXMATHSPANS, so parsing is cheap; native math layout is the real work.
Images
planned		 Alt text only, no request Streamdown loads the image, shows a placeholder while the URL is still streaming, falls back to "Image not available" on error, and offers a download control. The contract already fixes the rules: HTTPS only, four concurrent requests, cancellation.
Streaming animation and caret
not planned		 None animated (fadeIn, blurIn or slideUp, per word or per character, stagger, maxBacklogMs), caret (▋ or ●), isAnimating, onAnimationStart and onAnimationEnd. This is the most visible difference in a chat UI. Natively it would be alpha keyed to each character's distance from the snapshot tail, with the already-visible count carried across snapshots.
Styling and theming
planned		 System colors in light and dark only Streamdown takes className, a Tailwind prefix, components overrides and shikiTheme. The native equivalent is a theme object for fonts, sizes, colors and spacing per element. The contract defers this until "the feature set is fixed", but adopters will ask for it first.

Medium impact

Useful for real model output, but each can ship after the chat basics.

Streamdown featureDownstream todayNotes
Mermaid diagrams
not planned		 Fenced code plugins.mermaid with pan and zoom, full screen, and export as SVG, PNG or .mmd. Heavy on native: likely a web view or a server-side render. Better served by fence-language renderers below than by the core.
Custom renderers by fence language
contract change		 None plugins.renderers: [{ language, component }] replaces one fenced block with a component that receives code, isIncomplete and meta. This is narrower than per-node renderers and is the natural route for diagrams, charts and tool UIs. The "custom renderers: none" row in docs/api.md rules it out today; it needs a segment type that hosts a React child.
Link safety
not planned		 onLinkPress only linkSafety.onLinkCheck plus a confirmation modal, on by default. Downstream never opens URLs, so the host app can already do this; only a documented example is missing.
Wider link policy
not planned		 Absolute http, https, mailto Streamdown also allows tel:, and relative URLs resolved against a defaultOrigin through rehype-harden.
disableAutolinkProtocols
not planned		 Always on For example, stop bare emails from becoming mailto: links. md4c runs with MD_DIALECT_GITHUB, so permissive autolinking cannot be switched off.
Safe raw HTML subset
contract change		 All HTML shown as source rehype-raw and rehype-sanitize render tags such as <sub>, <sup>, <br>, <details> and <kbd>, plus allowedTags, literalTagContent for mention tags, fallbackComponent and normalizeHtmlIndentation. Rendering <br>, <sub> and <sup> alone would clean up a lot of model output. md4c's MD_FLAG_SUPERSCRIPTS, MD_FLAG_SUBSCRIPTS and MD_FLAG_HIGHLIGHT are a syntax-based alternative.
Table height and full screen
not planned		 Horizontal scroll only tableMaxHeight (default 300) with vertical scroll, and a full-screen view.
CJK handling
not planned		 Plain CommonMark rules @streamdown/cjk fixes emphasis next to CJK punctuation (remark-cjk-friendly) and ends autolinks at 。，） and similar. md4c uses standard flanking rules, so text like **太字**。 probably fails the same way. Worth a fixture test before deciding.

Low impact or web-specific

Mostly React or DOM extension points that the native segment design already covers or does not need.

  • translations and icons. Only matter once controls ship; the control labels should be overridable from the start.
  • mode="static", BlockComponent, parseMarkdownIntoBlocksFn, useIsCodeFenceIncomplete. React extension points that native segments replace. A per-block isIncomplete is still needed if fence renderers land.
  • dir="auto". Downstream uses natural direction per paragraph, which is close. Streamdown counts the majority of strong characters, ignores code when deciding, and always renders code blocks left to right.
  • portal and Tailwind prefix. No React Native equivalent.

Where Downstream is ahead

Worth keeping as the gaps close.

  • Admonitions, which Streamdown does not render.
  • Native accessibility: heading and link roles, spoken task state, table rows in reading order.
  • A typed error model with generations and sequences, so stale results are dropped.
  • UTF-16 source ranges on link events.
  • Incremental parsing and text preparation on a native worker pool, off the JavaScript and UI threads.
  • Completed segments reused across snapshots, so only the active tail is rebuilt.

Suggested order

Items 1, 2, 4 and 8 need no network access and no heavy dependency.

  1. Theme and style propUnblocks adoption; every later feature needs styling hooks anyway.
  2. Code block header, copy, meta string, max heightKeep the fence meta string in the parser and add a code segment with its own chrome.
  3. Syntax highlightingShipped. Kept here so the order reads as it was planned.
  4. Streaming caret and fade-inThe biggest perceived-quality gap in chat.
  5. Fence-language renderersNeeds a contract change and a React-hosting segment; opens the door to diagrams without core dependencies.
  6. ImagesAlready specified in the contract.
  7. MathParsing is available in md4c; layout needs its own review.
  8. Sub, sup and line breaksThrough the safe HTML subset or md4c's syntax flags.

This keeps the rule from the feature matrix: plain prose stays independent of the heavier paths. Highlighting, images, math and diagrams must load only when a document uses them, and a document with no fenced code never loads a lexer.
