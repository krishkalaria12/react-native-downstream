What Streamdown has that Downstream does not

A feature-by-feature comparison against Vercel's Streamdown, the web renderer this project is benchmarked against. It lists what is still missing from the native renderer, what is only half built, and a suggested order for closing them.

Safe raw HTML subset
partial		 <br>, <sub> and <sup> rendered; every other tag still shown as source The allowlist is three strings in src/cpp/downstream/Scan.cpp, applied behind inlineHtml (on by default) with md4c's superscript and subscript syntax flags as an opt-in. Attributes are ignored and a self-closed script or a stray close tag is swallowed. Still out: <details>, <summary>, <kbd>, <mark>, and the configurable allowedTags, literalTagContent, fallbackComponent and normalizeHtmlIndentation.
Mermaid diagrams
partial		 No diagram engine; a fenced mermaid block can be drawn by the host plugins.mermaid with pan and zoom, full screen, and export as SVG, PNG or .mmd is not built in, and should not be. plugins.renderers is the supported path: a fenced block whose language is registered is drawn by that component in the same view, so pan, zoom, full screen and export are the adopter's own component rather than a core dependency.
CJK handling
partial		 CJK text renders, and fades per character Reveal units split on ideograph, kana, Hangul and fullwidth ranges (src/cpp/downstream/Reveal.cpp), and the highlighter offsets CJK runs correctly. Parsing is still plain CommonMark: no @streamdown/cjk equivalent for emphasis next to CJK punctuation, and autolinks still run past 。，） and similar. md4c uses standard flanking rules, so text like **太字**。 probably fails the same way. Worth a fixture test before deciding.
Code block line marks and token color overrides
partial		 Token colors override; line marks parsed but not drawn theme.syntax and markdownStyle.codeBlock.syntaxColors let a theme replace the highlighter's palette. meta.marks is parsed and kept, so a mark list can never reach a title, but it is not drawn as line backgrounds.
translations and icons
partial		 Every control label is overridable; icons are fixed translations is a Partial<MarkdownTranslations> covering the control labels, including the failure and image states. There is no icons prop: the glyphs are hardcoded per platform (Android drawables, iOS symbol helpers), so an adopter restyles a control's label but not its icon.
dir="auto"
partial		 Natural direction per paragraph Close to Streamdown's behaviour, and code blocks already render left to right like Streamdown. Not modelled: counting strong characters across the paragraph, and ignoring code spans while deciding.
React extension points
partial		 Native segments replace them mode="static", BlockComponent, parseMarkdownIntoBlocksFn and useIsCodeFenceInComplete are React surfaces with no native analogue, and none is needed. The one thing the design did owe is a per-block incomplete flag, and fence renderers now receive it as isIncomplete.

Still missing

Nothing in the contract, and nothing in the tree.

Streamdown featureDownstream todayNotes
Table height and full screen
not planned		 Horizontal scroll only tableMaxHeight (default 300) with vertical scroll, and a full-screen view. Column widths are already clamped through markdownStyle.table.minColumnWidth and maxColumnWidth, and code blocks have an expand control, so a table is the only block with no way out of a nested scroll. fullscreen is not among the four control actions, so an event naming it is dropped rather than reported.
Link safety
not planned		 onLinkPress only linkSafety.onLinkCheck plus a confirmation modal, on by default. Downstream never opens a URL itself, so a host app can already do this; what is missing is a documented example.
Wider link policy
not planned		 Absolute http, https, mailto Fixed in src/cpp/downstream/LinkPolicy.cpp, which rejects control characters and accepts those three schemes case-insensitively. Streamdown also allows tel:, and relative URLs resolved against a defaultOrigin through rehype-harden.
disableAutolinkProtocols
not planned		 Always on For example, stop bare emails from becoming mailto: links. The parser runs with MD_DIALECT_GITHUB, which includes md4c's permissive-autolink bit, so this is not a flag that is currently off but a dialect constant that would have to change.

Where Downstream is ahead

Worth keeping as the gaps close.

  • Admonitions, which Streamdown does not render.
  • Native accessibility: heading and link roles, spoken task state, table rows in reading order.
  • A typed error model with generations and sequences, so stale results are dropped.
  • UTF-16 source ranges on link events.
  • Incremental parsing and text preparation on a native worker pool, off the JavaScript and UI threads.
  • Completed segments reused across snapshots, so only the active tail is rebuilt.
  • Theming as a slot table the engine reads directly, with a Shiki converter, so a host can restyle every element without a second render pass.

Suggested order

All of these are contract changes or small parser work; none needs a heavy dependency.

  1. Table max height and a full-screen viewThe only remaining block with no escape from a nested scroll.
  2. A configurable HTML allowlistTurns the fixed three-tag list into allowedTags, and opens up <details> and <kbd>.
  3. Link policy: tel: and relative URLsA widening of the contract's scheme list rather than a new mechanism.
  4. Decide on autolink protocolsNeeds a dialect change, so it wants a fixture first to show what a stricter mode would cost.
  5. CJK emphasis and autolink boundariesSame caveat: write the failing fixture before deciding whether it is worth it.
  6. An icons propThe last stub of Streamdown's components surface, and small once the control labels are already overridable.

This keeps the rule the feature set was built on: plain prose stays independent of the heavier paths. Highlighting, images, math and diagrams must load only when a document uses them, and a document with no fenced code never loads a lexer. It is also why the heavy paths are absent from this list: they are opt-in packages, not a cost every adopter pays.
