# First-release feature behavior

This matrix applies to the controlled view and the native stream session on iOS and Android. The release scope comes from [the API contract](api.md#feature-scope). The example app has four screens: Example streams a live Markdown chat reply, Testing replays one source through Streamdown and Downstream, Bench replays a source through Downstream alone, and Stress streams several answers at once.

| Feature | iOS and Android behavior | Streaming behavior |
| --- | --- | --- |
| CommonMark and GFM text | Paragraphs, headings, lists, quotes, rules, emphasis, strikethrough, inline code, fenced and indented code, and task markers render as native text. | The active tail can change classification; completed snapshots match a fresh full parse. An open span renders literally by default. Provisional styling is implemented in `src/cpp/remend/` and is off until a session opts in; see [provisional styling](streaming-semantics.md#provisional-styling). |
| Tables | A valid separator classifies a table. Columns use the widest current cell, clamped to 56–280 points plus padding. Wide tables scroll horizontally; inline styles and validated links remain in cells. | Rows appear as their source completes. The visible table updates without discarding the user's horizontal scroll position. Column widths can grow when a longer cell arrives. |
| Code | Fenced code uses monospace text and is colored by its info string, from the vendored Lexilla lexers in `src/cpp/lexilla/` on the shared worker pool. One palette, modeled on GitHub's light and dark code themes, drives both platforms; punctuation stays the code text color. `syntaxHighlighting={false}` keeps it plain. A block with no language, an unknown language, or over 64 KiB of code stays plain. | Open fences show incoming lines before the closing fence arrives, and are colored as they grow. A pass colors only the last incomplete line, so a settled block's tokens are the same whether it arrived in one piece or a thousand. A settled block is finished inside the pass that colors it, so a block too large for the per-pass time budget is still colored whole rather than left part-colored with nothing to finish it. Tokens change only colors, so selection, copy, and accessibility text are unaffected. |
| Images | The renderer shows alt text and makes no image request. | A partial image destination remains non-actionable, including when the URL inside it is already complete. |
| Math and raw HTML | Math source and delimiters remain literal. Raw HTML is visible text, never executed. | Partial syntax remains text until a valid Markdown construct changes its classification. |
| Links | Complete absolute `http:`, `https:`, and `mailto:` targets can emit `onLinkPress` with the full Markdown source range. The package does not open URLs. | Incomplete and disallowed destinations cannot emit an event. A bare URL inside an unfinished `](` is left as text, because md4c's permissive autolinks would otherwise offer a target the next chunk can move or remove. A bare URL in prose still becomes a link. |
| Selection and copy | The `selectable` prop enables native text selection in text segments. Copy returns visible text. The controlled prop or `stream.getSource()` provides the complete canonical source. | Completed text segments retain their selection when their native view is reused. Selection cannot cross a table or segment boundary. |
| Accessibility | Native reading order includes headings, individual link-role elements, and spoken checked or unchecked task state. Table rows are available in reading order. | Accessibility content follows the current snapshot and does not expose superseded text. |
| Font scale, RTL, colors | Text follows system font scale and natural writing direction. List and quote decorations follow the paragraph direction. Colors follow the system light or dark appearance. Wrapping is advance-based on every Android version, including 15 and later, where the platform would otherwise break lines on glyph bounds and drop the last word of a line. | Layout updates when the view's font scale, width, or appearance changes. |

Network images, native math layout, link long press actions, the code block header, and per-block copy controls belong to a later release. Their absence keeps plain prose independent of those heavier paths. A document with no fenced code never loads a lexer at all.

## Device checks

Run the example on both platforms with a development build. The Example screen needs an `EXPO_PUBLIC_OPENAI_API_KEY` in `example/.env`; without one it shows a setup note instead of calling the API. The Testing and Bench screens replay the documents in `benchmarks/samples.ts` and need no key. The Example screen exercises the first-release forms as live text, and the Testing screen replays the same forms in full and incremental parse modes.

1. With VoiceOver or TalkBack, traverse headings, task items, links, and each table row. Check link activation and task state announcements.
2. Select and copy text, then compare it with the visible text. Compare `getSource()` with the exact appended Markdown after a stream finishes.
3. Scroll a wide table horizontally while a new row streams in. Its position should stay put. Replay or reset the stream and check that a different table starts at the leading edge.
4. Replay a code-heavy sample, such as `code-streaming` or `code-languages` in `benchmarks/samples.ts`, in both appearances. Colors should follow the system appearance, code should stay selectable and copyable as plain text, and `syntaxHighlighting={false}` should remove every color without changing a character.
4. Rotate the device, enlarge system text, switch light and dark appearance, and revisit the RTL case. Check wrapping, mirrored decorations, and table overflow. On an Android 15 or later image, render a paragraph in an overhanging font such as `cursive` and confirm the last word of every line is painted.
5. Scroll between active and completed messages. Check that old content does not reappear after a cell is recycled or a session resets.

Automated parser and controller tests cover source preservation, URL policy, prefix classification, and final parse equality. Native layout and accessibility checks require a device or simulator.
