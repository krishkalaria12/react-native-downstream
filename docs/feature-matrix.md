# First-release feature behavior

This matrix applies to the controlled view and the native stream session on iOS and Android. The release scope comes from [the API contract](api.md#feature-scope). The example app has six screens: Example streams a live Markdown chat reply, Controls exercises line numbers, fence titles, the height cap, and copy, download, wrap, and expand on code blocks and tables, Renderers draws fences with app components, including one that throws and one that loads lazily, Testing replays one source through Streamdown and Downstream, Bench replays a source through Downstream alone, and Stress streams several answers at once.

| Feature | iOS and Android behavior | Streaming behavior |
| --- | --- | --- |
| CommonMark and GFM text | Paragraphs, headings, lists, quotes, rules, emphasis, strikethrough, inline code, fenced and indented code, and task markers render as native text. | The active tail can change classification; completed snapshots match a fresh full parse. An open span renders literally by default. Provisional styling is implemented in `src/cpp/remend/` and is off until a session opts in; see [provisional styling](streaming-semantics.md#provisional-styling). |
| Tables | A valid separator classifies a table. Columns use the widest current cell, clamped to 56–280 points plus padding. Wide tables scroll horizontally; inline styles and validated links remain in cells. | Rows appear as their source completes. The visible table updates without discarding the user's horizontal scroll position. Column widths can grow when a longer cell arrives. |
| Code | Fenced code uses monospace text and is colored by its info string, from the vendored Lexilla lexers in `src/cpp/lexilla/` on the shared worker pool. One palette, modeled on GitHub's light and dark code themes, drives both platforms; punctuation stays the code text color. `syntaxHighlighting={false}` keeps it plain. A block with no language, an unknown language, or over 64 KiB of code stays plain. |
| Line numbers | `lineNumbers` is on by default, as in Streamdown. Numbers are drawn in a gutter beside the code, right-aligned, in the code font. The gutter stays still while the code scrolls sideways, its width comes from the digit count of the last number with a two-digit minimum, and it widens by one digit as a block crosses 99. A wrapped long line numbers only its first visual line. `lineNumbers={false}` hides numbers everywhere; a fence's `noLineNumbers` hides them for that block, and the prop wins over it. | Numbers exist only for code lines, so nothing flickers while a fence streams. A block whose meta arrives one byte at a time shows its language until its title's closing quote arrives, and never a wrong title. |
| Fence titles | A fence's `title=`, `filename=`, or `lang:path` replaces the language in the header, truncating in the middle so `…/components/Button.tsx` keeps its file name. Control characters and bidi embedding, override, and isolate characters are removed and the label is capped at 96 UTF-16 units. The spoken label keeps the language too, so a title cannot change what a screen reader calls the block. | The info string is parsed once where the block is reported, so a growing fence never reparses it. |
| Code height cap | `codeBlockMaxHeight` is 400 points by default, as in Streamdown, and `0` removes it. A taller block scrolls inside its own card and is never shorter than five lines, whatever the text size. A capped block shows a bottom fade while content is below, and flashes its scroll indicator the first time it becomes capped. A vertical drag at a capped block's edge scrolls the surrounding list instead, on both platforms. | A capped block follows its newest line while it grows. Scrolling away from the bottom stops that, scrolling back resumes it, and the offset survives the block settling. A block above a streaming one stays where the reader left it. | Open fences show incoming lines before the closing fence arrives, and are colored as they grow. A pass colors only the last incomplete line, so a settled block's tokens are the same whether it arrived in one piece or a thousand. A settled block is finished inside the pass that colors it, so a block too large for the per-pass time budget is still colored whole rather than left part-colored with nothing to finish it. Tokens change only colors, so selection, copy, and accessibility text are unaffected. |
| Images | `images` is on by default. An image-only paragraph becomes a picture of its own; a picture inside prose keeps its alt text, as before. Requests go through the platform's own image pipeline — `RCTImageLoader` on iOS and the app's Fresco pipeline on Android — so the app's HTTP stack, cache and URL handlers apply. `downstream::imageBox` is the only rule that decides a picture's size, on both platforms. A pending picture shows a placeholder, a loaded one its own pixels scaled to the column and to `image.maxHeight` and never up, and a failed, blocked or disabled one a line of alt text. `allowedImagePrefixes` defaults to `['*']`; a destination it refuses draws its alt text and is never fetched. A press on a picture outside a link emits `onImagePress` and the package opens nothing. | A partial image destination remains non-actionable, including when the URL inside it is already complete. A picture's size reaches the shadow node as a state update with no React render, so a load that finishes restacks the text under it rather than re-rendering the message. At most four requests are in flight, deduplicated by URL and requested size, and cancelled when no view wants one. |
| Math and raw HTML | `math` is off by default, so a document without it parses byte for byte as before and every formula stays literal. With it on, `$$…$$`, a `$$` line fence, and a ` ```math ` fence are display math; `$$…$$` alone in a paragraph is promoted to a formula block of its own. `singleDollarTextMath` is off, as in Streamdown, so currency is text. `\(…\)` and `\[…\]` are on by default and `math={{ brackets: false }}` turns them off; `\[…\)` stays inline where `\[…\]` is display, which is LaTeX's own distinction and not something the `$$` rewrite could recover. Raw HTML is visible text, never executed. Without a math engine linked a formula keeps its literal, is drawn in `math.errorColor`, and reports `onMathError`. | A formula keeps its last good layout while it streams, so it does not re-shape on every token. A formula that cannot be laid out keeps its literal and its delimiters, which is also what copy returns and what a screen reader reads through `MathSpeech`. Partial syntax remains text until a valid Markdown construct changes its classification. |
| Links | Complete absolute `http:`, `https:`, and `mailto:` targets can emit `onLinkPress` with the full Markdown source range. The package does not open URLs. | Incomplete and disallowed destinations cannot emit an event. A bare URL inside an unfinished `](` is left as text, because md4c's permissive autolinks would otherwise offer a target the next chunk can move or remove. A bare URL in prose still becomes a link. |
| Selection and copy | The `selectable` prop enables native text selection in text segments and is **on by default**, which changes the long-press gesture for an existing app. Copy returns visible text. The controlled prop or `stream.getSource()` provides the complete canonical source. An app that opens its own message menu on a long press passes `selectable={false}`. | Completed text segments retain their selection when their native view is reused. Selection cannot cross a table or segment boundary. Selection turns on per settled segment, so a streaming tail is never selectable while earlier paragraphs are. |
| Controls | `controls` is on by default. A fenced block gets a header with copy, download, a per-block wrap button, and an expand button that appears only on a block past the cap; a table gets a toolbar whose copy button opens a Markdown, CSV, and TSV menu and whose download button opens a CSV and Markdown menu. Copy is native: a table pastes as `text/html` so rows, columns, and alignment survive, with plain text as the fallback. Download opens the platform save dialog, `UIDocumentPickerViewController` on iOS and a `CreateDocument` contract on Android, and the user picks the location. A cancelled dialog is not an error. A control's own `onCopy`, `onDownload`, `onToggle`, and `onError` report the press and any failure. | A control turns on as soon as its own block is settled, so a finished code block can be copied while the rest of the answer is still streaming. A block that is still being written shows its controls disabled, so its header does not change height when it settles. Toggling wrap changes one block's layout and does not disturb any other block's. Expanding lifts the cap for one block, grows the card through a Fabric state update with no React render, survives later snapshots, and is cleared by `reset()`. |
| Accessibility | Native reading order includes headings, individual link-role elements, and spoken checked or unchecked task state. Table rows are available in reading order. | Accessibility content follows the current snapshot and does not expose superseded text. |
| Theming | `theme` and `markdownStyle` reach every slot on both platforms, and both read the rules from the engine rather than deciding them separately, so a theme means the same thing on each. Every color is a light and dark pair drawn by the platform's own dynamic-color mechanism, so a themed document follows an appearance change with no render. A slot the theme does not set draws the platform's semantic color, so it also follows increased contrast. Only metrics change layout: a colors-only change redraws without a measurement, and `maxFontSizeMultiplier` caps the platform font scale without being able to turn it off. |
| Font scale, RTL, colors | Text follows system font scale and natural writing direction. List and quote decorations follow the paragraph direction. Colors follow the system light or dark appearance. Wrapping is advance-based on every Android version, including 15 and later, where the platform would otherwise break lines on glyph bounds and drop the last word of a line. | Layout updates when the view's font scale, width, or appearance changes. |

| Fence renderers | A fenced block whose language the app registered is drawn by that component, in the same view: the component is measured at the content column, and the block takes the component's height with a code block's own margins. Quote bars and list markers are drawn beside it, and the column mirrors for RTL. Any fence without a mounted component draws the code card. | `isIncomplete` is true until the fence settles. A settled component keeps its instance and is not re-rendered for later snapshots, and `reset()` mounts a fresh one. |

Math typesetting needs an engine, which ships as the opt-in `react-native-downstream-math` package; without it a formula is readable source. Link long-press actions also belong to a later release. A document with no fenced code never loads a lexer at all, and one with no code or table block draws no control chrome at all. A document with no fenced code builds no gutter and no viewport and parses no fence meta. A document with no formula builds no math layout at all, and one with `math` off never scans for delimiters.

## Device checks

Run the example on both platforms with a development build. The Example screen needs an `EXPO_PUBLIC_OPENAI_API_KEY` in `example/.env`; without one it shows a setup note instead of calling the API. The Controls, Renderers, Testing, and Bench screens need no key. The Example screen exercises the first-release forms as live text, and the Testing screen replays the same forms in full and incremental parse modes.

1. With VoiceOver or TalkBack, traverse headings, task items, links, and each table row. Check link activation and task state announcements.
2. Select and copy text, then compare it with the visible text. Compare `getSource()` with the exact appended Markdown after a stream finishes.
3. Scroll a wide table horizontally while a new row streams in. Its position should stay put. Replay or reset the stream and check that a different table starts at the leading edge.
4. Open the Renderers screen. Confirm a bar chart, a Mermaid-free JSON renderer, and a lazy renderer each draw in place of their fence with the list marker and quote bar still beside them, that a renderer that throws shows the code card with working copy, and that a streamed chart appears in the same frame as its closing fence without remounting when later text arrives. Change a renderer's height mid-stream and confirm the text below moves without overlap. With VoiceOver or TalkBack, confirm each renderer is read between the paragraphs around it. Scroll a chat of thirty chart messages and confirm no chart appears in the wrong message.
5. Open the Controls screen. Confirm the gutter numbers begin at the fixture's `startLine`, that crossing 99 widens it without clipping, that a wrapped long line numbers only its first visual line, and that the gutter stays still while the code scrolls sideways. Copy a code block and compare the clipboard with the visible text, including an empty fence, which must paste as an empty string, and confirm no number is ever copied or read aloud. Scroll a 300-line block: it should hold a 400-point card and scroll inside, and a drag at its top or bottom edge should move the list instead. While a long fence streams, confirm the card follows the newest line, that scrolling up stops it, and that finishing leaves the offset alone. Expand should appear only on blocks past the cap and should grow the card without a React render. Copy each code block and compare the clipboard with the visible text, including an empty fence, which must paste as an empty string. Copy the table and paste into a spreadsheet to confirm the rows and columns survive, then again into a plain text field to confirm the fallback. Download a block and a table, and confirm the file name carries the block's extension rather than the `filename` you set. Toggle wrap on one code block and confirm no other block's layout changes. Choose **Held mid-stream**, which leaves a final fence open, and confirm that block's controls are disabled while every block above it can still be copied, downloaded, and wrapped. Send `controls={false}` and confirm both the code header and the table toolbar disappear without any block reflowing. Send `lineNumbers={false}` and confirm only the gutter goes, and `codeBlockMaxHeight={0}` and confirm only the cap does.
6. Replay a code-heavy sample, such as `code-streaming` or `code-languages` in `benchmarks/samples.ts`, in both appearances. Colors should follow the system appearance, code should stay selectable and copyable as plain text, and `syntaxHighlighting={false}` should remove every color without changing a character.
7. Rotate the device, enlarge system text, switch light and dark appearance, and revisit the RTL case. Check wrapping, mirrored decorations, and table overflow. On an Android 15 or later image, render a paragraph in an overhanging font such as `cursive` and confirm the last word of every line is painted.
8. Scroll between active and completed messages. Check that old content does not reappear after a cell is recycled or a session resets.

Automated parser and controller tests cover source preservation, URL policy, prefix classification, and final parse equality. Native layout and accessibility checks require a device or simulator.
