A caret and per-word fade-in for streamed text

Streamdown fades each new word in as it arrives and can draw a caret at the end of the stream. Downstream shows every chunk at once with no caret, which the gap analysis calls the most visible difference in a chat UI. This plan adds both. It takes Streamdown's prop names, defaults and scheduling, and moves the work to native code: the engine decides which characters are new and when each word starts, and each platform's existing draw pass applies the alpha. A frame of animation needs no React render, no Fabric state update, no relayout and no change to a cached rendering.

Builds onSyntax highlighting (#15), controls (#16), theming (#18) and code block chrome (#19), all merged on main at c353de8.
Compared againstStreamdown 2.7.0 (vercel/streamdown@976cf12) and its open PRs #619, #625 and #626; react-native-enriched-markdown@0.6.0
New dependenciesNone. CADisplayLink, Choreographer, TextKit 1 drawing hooks and Canvas clipping only.
Decision: the engine schedules reveals, the platforms only draw them, and fade state lives outside every cached rendering

When a view applies a snapshot, a per-view RevealTracker in C++ aligns the new document's visible text with the one the view last showed. Characters with no match are new. It splits them into word units and gives each unit a start time on a shared timeline, a port of Streamdown's createAnimateTimeline. Units are keyed by block index and UTF-16 offset in Block::text, the coordinate both platforms already map into their segment strings, so a fade keeps going when its segment is rebuilt, committed or swapped for a cached one.

Drawing is per frame and local to the view. iOS splits DSLayoutManager's glyph drawing into runs of equal alpha. Android draws a text segment in clipped passes. A display link runs only while a unit is still fading, and only the fading lines are redrawn. The caret is an inline placeholder that reserves its advance in the measured layout. The view draws it at the reveal frontier, so it never sits after words that have not appeared yet.

Other renderers

The closest native peer, the web libraries, and the stream-side alternatives.

react-native-enriched-markdown

streamingAnimation (default off) fades the text past the previous length on every update. On iOS, ENRMTailFadeInAnimator snapshots each foreground color in the tail and, on every CADisplayLink tick, writes it back into the text storage with a new alpha (addAttribute:NSForegroundColorAttributeName inside beginEditing). The fade is 200 ms with ease-out. On Android, TailFadeInAnimator puts a FadeInSpan (a CharacterStyle that multiplies the paint and underline alpha) on the tail and animates it with a ValueAnimator for 150 ms. New table rows and new block views fade with UIView alpha. Reduce Motion is respected.

Three things not to copy:

  • Every update cancels the previous fade by setting it to full alpha. A model that streams faster than 200 ms per chunk never shows a complete fade. The tail just jumps. Units with their own start times on one timeline avoid this.
  • The whole tail is one unit. There is no per-word cascade, so a 150-character burst fades as one block.
  • It edits the text storage every frame. That is an attribute edit through TextKit on every tick. It replaces dynamic colors with fixed ones while the fade runs, and it would be unsafe here, because Downstream's segment strings are shared by the rendering caches. Applying alpha in the draw pass changes nothing that is shared.

What to take: the per-segment hook, the fade for new table rows, and a Reduce Motion check written in from the start. react-native-streamdown simply passes streamingAnimation through to enriched-markdown and has no caret.

Web libraries and the stream side

  • FlowToken wraps each word in a span with CSS keyframes, as Streamdown's plugin does. It came first, and Streamdown issue #371 cites it as the model. It ships many effects (typewriter, drop-in, wave and more). Only fade and rise survive a native draw pass at no extra cost.
  • llm-ui does not fade. It throttles: it holds back a buffer of characters (15 by default) and reveals them at a rate fitted to how fast output has been arriving, so that pauses are smoothed out. Streamdown's smooth PR (#625) does the same at word granularity and reports about 700 small steps instead of 37 large jumps, at the cost of about one chunk interval of delay. This is the basis for phase 7.
  • AI SDK smoothStream paces on the server or in the transport: it re-emits deltas word by word with a 10 ms delay. It helps any renderer, but it only evens out arrival times; it does not animate. The two work together: smoothStream makes snapshots smaller and more frequent, and the timeline keeps each word's fade on schedule.
  • SwiftUI TextRenderer (iOS 18) is Apple's per-glyph hook: a renderer gets Text.Layout lines, runs and slices and draws each slice with its own opacity or transform. Downstream renders with TextKit 1 for iOS 15.1, so it uses the TextKit 1 equivalent, overriding drawGlyphsForGlyphRange:atPoint:. The shape of the solution is the same.

Constraints from the contract and the code

Rules from api.md and the earlier items that this one must keep.

  • Renderings are shared and immutable. A DSTextSegment or Android TextSegment is cached by identity, theme and scale (DSRenderedDocument.mm:948, RenderedDocument.kt:788), and equal controlled sources share one parse. Fade state cannot live in a segment's text, its spans or its PrecomputedText.
  • Measured height equals drawn height. The fade never changes layout. The caret does, so it goes into the measurement the same way chrome and CodeLayout do: in LayoutHint (RenderPreparer.h:29), the Fabric state and both rendering cache keys.
  • No React render per frame and no Fabric state update for animation. Snapshots already re-render (sessionRevision); animation frames must not.
  • Plain prose does not pay. With animated off, no tracker is created, no display link exists, and each draw override costs one nil check. With caret off, the rendering is byte-identical to today's.
  • Copy, selection, export and accessibility text are unchanged. The caret is never copied, selected, exported or read aloud. Hidden text is still in the accessibility tree; it is at most one backlog (about half a second) ahead of what is drawn.
  • Stale work cannot repaint. A new generation, a session change or a recycled view clears the tracker, in the same places resetScrollPositions runs (DownstreamMarkdownView.mm updateProps:, DownstreamMarkdownView.kt sourceChanged).
  • One rule, written once. As with CodeLayout.h, the decisions (what is new, the unit boundaries, the start times, where the caret goes) are in the engine. Kotlin mirrors only the per-frame easing, and one case table checks both.

Why time, not distance from the tail

The gap analysis sketched alpha as a function of "each character's distance from the snapshot tail". That ties the fade to the arrival rate. A 150-character burst would leave a long dim stretch that brightens all at once when the next burst arrives, and a slow stream would show almost no fade. Streamdown keys each word to wall-clock time on a shared timeline, so every word gets the same fade however the bytes were chunked. This plan does the same. What the analysis got right is that the state is a small amount of bookkeeping carried across snapshots, not something stored in the rendering.

Where state lives

  • Per view: a RevealTracker (C++). It holds the document the view last showed, the timeline cursor, and the active units (those not yet at full alpha). The iOS view owns it directly. Android holds a native handle, as it already does for documents by id.
  • Per session: the document last shown. SessionRegistry gains noteShown(id, document) and shown(id). A view that binds to a live stream, for example after a virtualized list scrolls it back into view, starts its tracker from what was already shown. It does not fade the whole message in again. Streamdown fades it all again on remount.
  • Per controlled view: nothing is shared. The first document a fresh controlled view shows counts as already seen. A message that mounts empty and then grows, the usual useChat pattern, fades everything after its first render.

Diff, units and timeline

src/cpp/downstream/Reveal.{h,cpp}: pure functions plus one small class, all host-testable.

// Reveal.h
enum class RevealSplit : uint8_t { Word, Char };
enum class RevealEffect : uint8_t { None, Fade, Rise };   // fadeIn, slideUp
struct RevealOptions {
  RevealEffect effect{RevealEffect::None};
  RevealSplit split{RevealSplit::Word};
  float durationMs{150};
  float staggerMs{40};
  float maxBacklogMs{320};
  CubicBezier easing{0.25f, 0.1f, 0.25f, 1.0f};          // CSS `ease`
};
/// A run of new visible text, in one block's text coordinates, with its start time.
struct RevealUnit {
  uint32_t block{0};
  uint32_t start{0};   // UTF-16, into Block::text
  uint32_t end{0};
  double startAt{0};   // ms, the platform's monotonic clock
};
/// For one block of `next`: the stretches that match the previous block's text.
struct AlignedRun { uint32_t nextStart, prevStart, length; };
std::vector<AlignedRun> alignVisibleText(std::u16string_view prev, std::u16string_view next);
/// Cuts new ranges into units: words with trailing whitespace glued on, CJK one
/// per character, a whole row for a table row, one unit for a block with no text.
void splitUnits(const Block &, uint32_t block, uint32_t from, uint32_t to,
                RevealSplit, std::vector<RevealUnit> &out);
/// A port of Streamdown's createAnimateTimeline: one cursor across passes.
class RevealTimeline { public: void schedule(std::span<RevealUnit>, double now, const RevealOptions &); /* … */ };
class RevealTracker {
public:
  /// Seeds the "already shown" document, from the session or a first render.
  void seed(DocumentHandle shown);
  /// Aligns `next` with the shown document, keeps the timing of units that
  /// still align, schedules new ones, and returns the active set.
  const std::vector<RevealUnit> &apply(const DocumentHandle &next, double now, const RevealOptions &);
  /// Drops units that are fully shown. False when nothing is left to draw.
  bool prune(double now, const RevealOptions &);
  void clear();
};
/// 0 before startAt, eased progress during the fade, 1 after.
float revealAlpha(const RevealUnit &, double now, const RevealOptions &);

1. What is new: aligning visible text

  • Fast paths. A block in the shared committed prefix (the same SharedList storage) or with an equal non-zero identity is entirely old and is never scanned. Most of a stream's blocks take this path, so an apply scans only the tail. A controlled source has no identities. It compares texts with == first, which is a memcmp, before aligning.
  • Alignment. A two-pointer walk with a skip budget. When the characters match, both sides advance. On a mismatch, the walk tries skipping up to 4 old characters, which handles a removed **, ~~, `, [ or ](, and a skip counts only if the next two characters also match. Next it tries skipping up to 4 new characters. If neither works, the rest of the new block is new. The walk is O(n·4) per changed block. A block over 64 KiB uses Streamdown's rule instead: offsets below the old length count as old.
  • Same index, any kind. Blocks are paired by index. A paragraph that becomes a setext heading keeps its text, so nothing fades again. Literal pipe text that becomes a table row does not align, so the row fades in. That is a real visual change and a fade suits it.
  • The invariant. A character that was drawn at full alpha is never scheduled again. An active unit is remapped through the aligned runs and keeps its startAt. A unit that loses its characters is dropped. This is what #619 fixes in Streamdown.
  • Continuations. A word split across two snapshots (wor, then world) gives a new range that touches an active unit with no whitespace between. It joins that unit and fades with it. If the earlier part has already finished, the rest gets a unit of its own. Streamdown gives the rest a zero-duration fade, so it appears at once.

2. Units

  • Word. A maximal run of non-whitespace plus the whitespace after it (Streamdown #535). An ideograph, kana or Hangul syllable is its own unit, and so is each piece of CJK punctuation. A line break ends a unit.
  • Char. One grapheme-ish cluster: a surrogate pair, a base character with its combining marks, variation selectors and ZWJ continuations, or a regional-indicator pair. Whitespace is glued to the previous unit, as in splitByChar. This is approximate segmentation, not full UAX #29, and the tests cover the common emoji and Indic cases.
  • Blocks without words. A rule, an empty fence (its ​ placeholder) and a table row are one unit each. A row is one unit even in char mode, because row cells are drawn by the grid view, not by a text layout.

3. The timeline

RevealTimeline::schedule is Streamdown's beginPass, then take, then commitPass, run once for each applied snapshot. The cursor resumes from the last commit but is never more than maxBacklogMs ahead of now. Units start at the cursor, spaced by stagger. If the batch would end past the budget, the step shrinks to fit, but never below 4 ms. With stagger: 0 the step is 0 and has no floor. Constants: MAX_ANIMATION_BACKLOG_MS = 320 and MIN_STAGGER_STEP_MS = 4.

Times are in milliseconds on the platform's monotonic clock, CACurrentMediaTime or SystemClock.uptimeMillis, read when the snapshot is applied on the UI thread. The worker does not read them, because it can prepare a snapshot that is never shown. Under Android's animator duration scale, duration, stagger and the backlog are multiplied by the scale. A scale of 0 turns the fade off.

4. Easing

JavaScript turns the easing string into four control points: linear, ease, ease-in, ease-out, ease-in-out and cubic-bezier(x1, y1, x2, y2), with x clamped to [0, 1]. Anything else, such as steps() or linear() with stops, warns once and uses ease. The engine solves the curve with a Newton-then-bisection CubicBezier, written fresh here and tested against CSS reference values. Android evaluates the same curve with PathInterpolator(x1, y1, x2, y2), and a shared case table bounds the difference at 0.002.

Drawing the fade

One hook per draw pass that already exists. A frame redraws only the lines that hold an active unit.

Mapping units to segments

A unit's block and offset map straight into a segment. iOS segment strings hold each block's text verbatim at blockRanges[i] (DSRenderedDocument.mm:463). Android has the same in accessibleBlocks[i].start. A code body is a one-block text segment, and a table row is a block. Each segment view asks its host for runsIn(range, now): the segment-local ranges whose alpha is below 1, in text order. Alpha falls along text order, so the answer is a fully shown prefix, a short fading band and a hidden suffix. A segment whose blocks have no active unit gets an empty answer and draws exactly as it does today.

iOS: alpha runs in DSLayoutManager

  • Text. Override drawGlyphsForGlyphRange:atPoint:. With no runs, call super. Otherwise split the glyph range at run boundaries. Draw the shown prefix with super. Draw each fading run inside CGContextSaveGState, CGContextSetAlpha (and for slideUp a CGContextTranslateCTM of 4·(1−p)), super and restore. Skip the hidden suffix. Drawing a glyph subrange is exact: glyphs are already shaped and positioned, so kerning, ligatures and Arabic joining are unaffected, and units end after whitespace, so a split never falls inside a word.
  • Backgrounds and decorations. drawBackgroundForGlyphRange:atPoint: uses the same split, so inline-code backgrounds and the selection highlight fade with their text. List markers and task boxes, drawn in the same override (DSLayoutManager.mm), take the alpha of their block's first unit. Rules take their block's single unit. Quote bars are drawn at full alpha, as Streamdown draws borders.
  • Invalidation. On each tick the host calls invalidateDisplayForCharacterRange: on each affected layout manager, for the union of active ranges plus the ones that just finished, so their last frame is drawn at full alpha. TextKit redraws only those line fragments. There is no text storage edit, no glyph invalidation and no layout.
  • Code cards and tables. The gutter (DSCodeGutterView) draws each number with the alpha of its line's first character. A new card's background, border and header fade with the block's first unit. Its body text fades by its own units, so the card does not multiply them. A table row's cells, row fill and grid segment fade with the row's unit in DSTableGridView's drawRect:.

Android: clipped passes in TextSegmentView.onDraw

A TextView draws its whole Layout, and spans cannot be added: the text is a shared SpannableStringBuilder or PrecomputedText. So the existing draw (inline-code backgrounds, super.onDraw, decorations; DownstreamMarkdownView.kt:921) becomes drawContent(canvas) and runs in clipped passes:

  1. One pass for everything except the fading band and the hidden suffix: clipOutPath on API 26 and later, clipPath(path, Region.Op.DIFFERENCE) on API 24 and 25, with the band's selection path from layout.getSelectionPath. Layout.draw draws only the lines inside the clip.
  2. One pass per alpha bucket in the band: saveLayerAlpha over the bucket's bounds, clip to the bucket's path, and drawContent again (for slideUp, translated). Units are grouped into at most 8 buckets of nearly equal alpha, so a compressed burst costs no more than 8 layers per frame.
  3. Nothing for the hidden suffix.

A selection path covers a character range from line top to line bottom, following wrapping and bidi. Because whitespace is glued to the end of each unit, a clip edge falls after a space, which keeps italic overhang and kerning from being cut. When a unit opens a list item, its region is widened to the leading margin so the marker fades with the word. The gutter, card, table grid and rules work as on iOS: CodeGutterView, CodeSegmentView and TableGridView read alpha from the host. The tick is postOnAnimation, which invalidates the affected views.

Why not spans on Android? enriched-markdown's FadeInSpan works because each of its views owns its text. Here a committed segment's text is cached and can be shown by two views of the same controlled source, and adding spans would mean copying the tail's PrecomputedText. Clipping changes nothing that is shared. If Phase 5 measures the layer cost as too high on low-end devices, the fallback is a fade span on the uncommitted tail only, which belongs to a single session and a single view. Committed text would keep the clip.

The ticker

  • One per host view: CADisplayLink in NSRunLoopCommonModes (so it runs while the list scrolls), or a postOnAnimation loop. It starts when apply returns active units and stops when prune reports none.
  • When the view leaves its window, all active units are finished at once and the link stops. A recycled view clears the tracker.
  • Each tick costs a prune, one invalidation per affected segment, and a redraw of a few line fragments. Budget: 0.5 ms of UI-thread time per frame for a typical tail, measured in Phase 6.

The caret

Part of the rendering, because it takes space. One placement rule, written in the engine.

// Caret.h
enum class CaretKind : uint8_t { None, Block, Circle };
enum class Animating : uint8_t { Auto, On, Off };   // Auto: follow the document
struct CaretSpec {
  CaretKind kind{CaretKind::None};
  Animating animating{Animating::Off};
  bool operator==(const CaretSpec &) const = default;
};
enum class CaretPlace : uint8_t { None, AfterText, OwnLine };
/// AfterText: after the last character of the last block (prose, or a fence
/// still open). OwnLine: a line of its own after the last segment, or alone in
/// an empty document. None: no caret.
CaretPlace placeCaret(const Document &, const CaretSpec &);
  • When it shows. kind != None, and either animating == On or animating == Auto while Document::streaming is true. streaming is a new field that the session sets on every snapshot before finish(); controlled documents leave it false. This is the only way isAnimating reaches the native rendering.
  • Where it goes. After the text when the last block is a paragraph, a heading or a list item (at any depth), or a fence that is still open. On a line of its own when the document is empty or ends with a table, a closed fence or a rule. That is where the next block's first line will appear, so when text arrives the caret line is replaced without a jump.
  • Open fences. A new Block::fenceOpen is set by MarkdownParser when md4c ended a fenced block at end of input with no closing fence after its last line. This is checked with scan::closesFence, so nested fences count too. watchOpenFence (IncrementalParser.cpp:577) knows this only for top-level fences in incremental mode.
  • In the layout. A breaking space, then a placeholder with the last character's font: an NSTextAttachment with a clear image and explicit bounds on iOS, and a ReplacementSpan that draws nothing on Android. The placeholder's height stays within the font's ascender and descender, so the line height never changes, and a full line wraps it to the next line. It goes in the last text segment's string (or the code body's). An own-line caret is a synthetic one-line text segment with normal block spacing.
  • Drawing. The segment draws the shape: a rounded bar of 0.5 em spanning cap height plus half the descender for block, and a 0.55 em dot centered on the x-height for circle. These are the proportions of U+258B and U+25CF in SF Pro. The color is the foreground at the last shown character, resolved for the current appearance, which matches Streamdown's inherited color. The position is the end of the last started unit when a fade is running, and the placeholder otherwise.
  • Measurement. CaretSpec is added to LayoutHint (and its operator==), to DownstreamMarkdownState and getDynamic(), to the iOS key (DSRenderedDocument.mm:1006), and to the Android key (RenderedDocument.kt:829). Only the last segment changes. When it is a committed chunk, the caret variant is cached under its own key, so a pause between blocks builds it once. A finished session snapshot is prepared with the caret already resolved to None, so the last frame does not miss the worker cache.
  • Never text. Copy strips the placeholder, as it strips kPlaceholder (DSSegmentViews.mm:26). Accessibility is built from block ranges, and the caret lies outside them. Exports read the Document, which has no caret.

Public API

Streamdown's names and defaults. The only addition is that a stream works out isAnimating by itself.

// src/types.ts
export type MarkdownAnimateOptions = Readonly<{
  /** 'fadeIn' by default. 'blurIn' and other names draw as 'fadeIn' and warn once. */
  animation?: 'fadeIn' | 'slideUp' | 'blurIn' | (string & {});
  /** Per unit, in ms. 150 by default. */
  duration?: number;
  /** A CSS timing keyword or cubic-bezier(). 'ease' by default. */
  easing?: string;
  /** 'word' by default. CJK text is split per character in either mode. */
  sep?: 'word' | 'char';
  /** Delay between units, in ms. 40 by default; 0 turns the cascade off. */
  stagger?: number;
  /** How far ahead of now a burst may be scheduled, in ms. 320 by default. */
  maxBacklogMs?: number;
}>;

type MarkdownViewBaseProps = Readonly<{
  // …existing props
  /** Fade new text in while the view is animating. Off by default. */
  animated?: boolean | MarkdownAnimateOptions;
  /**
   * Whether text is still arriving. A controlled view must say so, as in
   * Streamdown. A stream view follows its controller: on from the first append
   * until finish(). An explicit value overrides that.
   */
  isAnimating?: boolean;
  /** A caret after the newest text while animating. None by default. */
  caret?: 'block' | 'circle';
  /** isAnimating turned on, including on mount. */
  onAnimationStart?: () => void;
  /** isAnimating turned off. Fades still running finish afterwards. */
  onAnimationEnd?: () => void;
}>;
  • Native props (codegen): animation: WithDefault<'none' | 'fadeIn' | 'slideUp', 'none'>, animationSplit: WithDefault<'word' | 'char', 'word'>, and animationTiming: ReadonlyArray<Double> holding [duration, stagger, maxBacklog, x1, y1, x2, y2]. The array form is the one themeValues uses: it compares as a vector and one field carries it. Also animating: WithDefault<'auto' | 'on' | 'off', 'off'> and caret: WithDefault<'none' | 'block' | 'circle', 'none'>.
  • Normalization (src/animation.ts): animated: true gives the defaults. A negative or NaN number falls back to its default with one warning. The resolved value is kept by value, like useStableResolved, so an inline literal such as animated={{ animation: 'fadeIn' }} sends nothing new when it re-renders (Streamdown's animatedKey). A stream view sends animating: 'auto' unless isAnimating is given; a controlled view sends 'on' or 'off'.
  • Callbacks. For a controlled view, a useLayoutEffect on isAnimating with Streamdown's mount rule. For a stream view, the controller gains internal started and finished notifications that StreamMarkdown subscribes to (createMarkdownStream.ts); a reset() starts a new cycle. No native events are added.
  • Not added: a theme slot for the caret color (it follows the text, as in Streamdown), caret blink, and createAnimatePlugin.
  • Contract edits. docs/api.md: a "Streaming animation" section with the props, the placement rule, Reduce Motion and the blurIn fallback, plus an implementation-status row. docs/streaming-semantics.md: a paragraph saying animation is drawing only and never changes the canonical source, the settled parse or source ranges. docs/feature-matrix.md: rows for the fade, the caret and Reduce Motion. The gap analysis row is marked shipped when this lands.

Platforms (Simulator and emulator)

  • Words fade in order with a visible cascade; a 2 KB burst finishes within about half a second; a slow drip fades each word fully; nothing that has been shown flashes again when a bold, link or code span closes.
  • Finish lets the last words complete; reset fades the new source from its first word; scrolling a live message off screen and back does not fade it all again.
  • Markers and task boxes fade with their first word; a rule fades; a new code card and its gutter fade with the code; a new table row fades; inline-code backgrounds and link underlines never show before their words.

Risks and open questions

Defaults and open questions decided; the rest are risks with their mitigation.

Question or riskRecommendation
Defaults of animated and caretdecided off Streamdown parity. Animation is a product choice, and an app that renders history would not want it on by default.
UITextView redraw through drawGlyphsTextKit 1's container view draws through the layout manager, and invalidateDisplayForCharacterRange: is the documented trigger. The Phase 0 spike confirms it before anything else is built. If it fails, the fallback is NSLayoutManager temporary attributes, which are drawing-only, need no relayout and are per view, at the cost of computing faded colors.
Android layer costCapped at 8 saveLayerAlpha passes per segment per frame, with bounds limited to the band. Measured in Phase 5 on an API 24 image and a low-end profile. The fallback is a tail-only fade span, as described under Drawing.
Hidden text still takes up spaceInherent to fading laid-out text; Streamdown behaves the same. At most maxBacklogMs + duration (about 470 ms) of blank tail. Drawing the caret at the frontier keeps the writing point visible.
Height changes on finishA caret that wrapped to its own line is removed by the final snapshot, so the view shrinks by one line, as with Streamdown's ::after. Accept and document it.
Alignment misfiresThe 4-character skip budget with a two-character confirmation can, in rare cases, call text new and fade it again. That is visible but harmless, and bounded by the property tests. Never calling new text old matters more, and the count fallback ensures that.
Caret inside an open fencedecided yes Streamdown hides it there for CSS reasons. Natively it is a cursor where the code is being written. Revisit if a cursor that looks like code text confuses readers.
onAnimationEnd timingdecided parity It fires when isAnimating turns off, as in Streamdown, even though the last fades run up to about 470 ms longer. A native "reveal finished" event can be added later if apps want to show message actions after the text has fully appeared.
Open: blurInfallback now Options: Android 12+ RenderEffect on a per-band layer; on iOS, drawing a run three to five times at small offsets with low alpha. Evaluate after the core ships; until then it draws as a fade and warns once.
Controlled first render shows without fadedecided Differs from Streamdown, which fades everything on mount. The usual pattern (mount empty, then grow) fades as expected, and remounting a long message in a virtualized list no longer fades it all again. Documented.
Screen reader focus on hidden wordsHidden words stay readable in the tree for under half a second. No change is planned. If testing shows VoiceOver focusing on blank space, exclude the hidden suffix from element frames until it starts.

Follow-ups this unlocks

Not part of this item.
