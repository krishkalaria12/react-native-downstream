Sub, sup and line breaks, without a sanitizer

Models write H<sub>2</sub>O, x<sup>2</sup>, footnote markers like <sup>1</sup>, and above all <br> inside GFM table cells, because a table row has no other way to break a line. Streamdown renders all of these. Downstream shows the tags as literal text, as the first-release contract requires. This plan closes the "Sub, sup and line breaks" item of the Streamdown gap analysis by recognizing exactly five inline tags in the parser, mapping them onto two new inline style bits and the line break the engine already has, and leaving every other tag as visible text.

Builds onTheme and style (#18), copy and download controls (#16), the remend preview port, and math and images (#21). All are treated as merged.
Compared againstStreamdown 2.7.0 and remend 1.4.0 (vercel/streamdown@1ddd8f4), hast-util-sanitize's GitHub schema, Tailwind's preflight, and react-native-enriched-markdown@c10ab56
New dependenciesNone. md4c already reports inline HTML as MD_TEXT_HTML pieces, and both platforms already raise footnote references with a size scale and a baseline shift.
Decision: an allowlist of five inline tags read in the parser, not an HTML renderer

<sub>, </sub>, <sup>, </sup> and <br> (with <br/>, <br /> and any letter case) are matched inside the MD_TEXT_HTML pieces md4c already hands the DocumentBuilder. A matched tag contributes no text: sub and sup set InlineStyle::Subscript or InlineStyle::Superscript on the text between them, and br appends the same '\n' a hard break does. Any other tag, and any tag inside code, stays literal exactly as today. md4c's own ^sup^ and ~sub~ syntax is offered as an opt-in only, because with it on 2^10 and 3^5 becomes a superscript and ~strike~ stops being strikethrough.

What the engine does today

md4c 0.6.0 as vendored, with MD_DIALECT_GITHUB, probed through its callbacks.

md4c already does the hard part. A complete inline tag arrives as its own MD_TEXT_HTML callback, separate from the text around it, and Markdown inside the tags is parsed normally. DocumentBuilder::text sends that piece to its default branch, which appends the bytes as visible text. That one branch is the whole reason the tags are literal.

Design

Everything new lives in the parser and the two run appliers. Segments, measurement and Fabric state are untouched.

md4cUnchanged. Reports MD_TEXT_HTML pieces, or MD_SPAN_SUPERSCRIPT and MD_SPAN_SUBSCRIPT when the opt-in flags are set.

1. The tag matcher

A pure function in src/cpp/downstream/Scan.h, next to the scanners the parser and the preview pass already share: InlineTag matchInlineTag(std::string_view piece) returning None, BreakTag, SubOpen, SubClose, SupOpen or SupClose. It is table-driven (name, opens, closes, void) so a later tag is one row. It does not need to be a general HTML tokenizer: md4c has already proven the piece is one well-formed tag, so the matcher only reads the name, case-insensitively, and checks what follows it. The same table drives the preview pass's prefix test, so the two can never disagree about which tags exist.

2. Builder state and scoping

  • Depths, not spans. subDepth_ and supDepth_ beside strongDepth_. A close tag with depth zero is swallowed (no text), which is what an HTML parser does with a stray end tag and what keeps \<sub>y</sub> from showing a dangling </sub>.
  • Scope. Both depths reset in beginLeaf and in beginCell. An unclosed <sub> runs to the end of its paragraph or its cell and never leaks into the next block or column, which is how a browser closes it at </p> or </td>. Because the state never crosses a block, committed-block identity and the incremental parser's block reuse are unaffected.
  • Innermost wins. currentStyles() sets one of the two bits, the one opened last, so <sup>a<sub>b</sub></sup> lowers b rather than cancelling. A small two-entry "last opened" marker is enough; nesting the same tag twice does not shift further, matching enriched-markdown's "cannot nest" rule and avoiding unbounded shifts.
  • Footnote references win. A [^1] inside <sup> keeps only FootnoteRef, so it is raised once, not twice.
  • Where tags are not tags. Code spans and code blocks never produce MD_TEXT_HTML. Math is verbatim TeX. An HtmlBlock other than a lone <br> keeps its literal text, because a <div> block's contents are not parsed as Markdown and showing half its tags would be worse than showing all of them.
  • Inside an image. A matched tag inside MD_SPAN_IMG adds nothing to the alt text, so Image::alt stays plain and promoteImageParagraph's text comparison still holds. Style bits inside alt text are kept; alt text is drawn secondary anyway.
  • Source ranges. noteSourceText still sees the tag's bytes, so a block's source range, a link's range and the commit boundary cover the tag even though it adds no text.

No new block kind, field or segment. <br> is a '\n' in Block::text, which is already what a hard break, a soft break and an image-block separator are, so selection, accessibility text, copy and every offset rule already handle it. sameBlock compares runs, so the new bits take part in committed-segment identity with no change. The Kotlin mirror adds STYLE_SUPERSCRIPT and STYLE_SUBSCRIPT to NativeDocument.kt; the JNI layer already passes run.styles through unmasked.

4. Drawing

Both platforms already draw a raised, smaller footnote reference, so this is the same code with two more cases rather than a new mechanism. applyRuns in DSRenderedDocument.mm scales the run's size and sets NSBaselineOffsetAttributeName (positive for up, negative for down). RenderedDocument.kt adds a RelativeSizeSpan and the existing BaselineShiftSpan with a signed fraction. The scale and shift come from four new theme slots, read through ThemeLayout.h helpers beside footnoteSizeScale and footnoteRaise. Inline code inside a superscript takes both the code face and the scale. An inline formula inside one keeps its own attachment size; scaling a formula is a follow-up if anyone asks.

The line must not grow. Streamdown's line height is unchanged by a superscript because Tailwind's preflight sets line-height: 0 on sub and sup. On Android, baselineShift does not change the paint's font metrics, so StaticLayout keeps the line height already. On iOS, TextKit grows a line fragment to fit a baseline offset, which is why a footnote reference may already open its line slightly. Phase 3 measures this on the Simulator. If a line with a superscript is more than half a point taller than the same line without one, a paragraph that contains a script or footnote run gets maximumLineHeight equal to its minimumLineHeight, unless it holds an inline math attachment.

5. Copy, export and speech

  • Plain text. Selection copy and getSource() are unchanged in kind: selection copies E=mc2, which is what a browser copies from Streamdown's <sup>; getSource() returns the tags as written.
  • Table Markdown. appendMarkdownCell wraps a script piece in <sup> or <sub>, outside code and inside emphasis. These tags are appended unescaped, unlike text, where kMarkdownEscapes still escapes a literal <. A cell's '\n' is already written as <br>.
  • Table HTML. appendHtmlCell gains <sup>/<sub> and, newly, writes a cell's '\n' as <br>. Without that, a paste into a spreadsheet would collapse the break to a space.
  • CSV and TSV. Unchanged: a superscript is its text, and a newline is quoted or escaped as today, which is Streamdown's tableDataToCSV and tableDataToTSV behavior.
  • Speech. A screen reader reads H2O and x2, as VoiceOver and TalkBack read a web <sup>. Saying "superscript" on every footnote marker would be noise. This is a deliberate choice; see decisions.

Line break rules

The one place where Downstream's display differs from HTML's, so the mapping cannot be one break per tag.

Downstream renders a soft break as a line break (api.md: "Soft line breaks display as line breaks, as the fixture contract requires"); HTML renders it as a space. A writer who puts <br> at the end of a line means one break, and in Streamdown gets one. Mapping both the tag and the soft break to '\n' would give a blank line instead. The rule:

Breaks are counted per stretch. A stretch is a run of soft breaks, hard breaks and <br> tags with no text between them. Each <br> and each hard break (two spaces or a backslash) is one line break; soft breaks count only in a stretch that has neither, which is today's behavior. Spaces directly around a <br> are dropped, as HTML's whitespace collapsing drops them. The builder holds the stretch's count and writes the newlines when the next text arrives, so nothing it has appended is ever taken back.

A block that is only <br> tags and whitespace becomes a Paragraph of n empty lines, with the same zero-width placeholder an empty code fence uses so it measures one line per tag; copy and accessibility strip the placeholder, as they already do for code. Public API

One prop, one option object, two style keys, one preview bit. All additive.

  /** `~x~` is a subscript instead of strikethrough. Off, as in Streamdown. */
  subscript?: boolean;

Parse options become one bitmask

inlineHtml and syntax change what a source parses to, so like math they are part of a parse's identity and have to reach parseMarkdown, the incremental parser, the preview pass, the shadow node and the session. Today that path carries MathOptions and the native mathFlags prop through about twenty files. Rather than thread a second value beside it, the first phase renames MathOptions to ParseOptions, MathParseFlags to ParseFlags and mathFlags to parseFlags, keeping bits 0 to 2 as they are, and adds:

BitNameDefaultEffect
0–2MathEnabled, SingleDollar, Bracketsas todayUnchanged.
3InlineHtmlonThe tag matcher runs. Off: every MD_TEXT_HTML piece is literal, exactly today's parse.
4SuperscriptSyntaxoffAdds MD_FLAG_SUPERSCRIPTS.
5SubscriptSyntaxoffAdds MD_FLAG_SUBSCRIPTS.

src/math.ts's resolver becomes the general src/parseFlags.ts, still the only file that writes the bits. A document with no tags parses byte for byte as before under the new default, so every existing golden holds; only documents that contain one of the five tags change.

Streaming

An open tag needs no repair. A half-arrived tag can flash; the preview pass can hide it.

  • Open tag, no closer yet. H<sub>2 already lowers the 2, because the scope rule runs an unclosed tag to the end of its block. When </sub> arrives the following text is ordinary. Nothing reflows that was settled, and the finished document is a plain parse of the bytes the writer sent, as docs/streaming-semantics.md requires.
  • Half a tag at the tail. x<sup>2</sup shows 2</sup raised for one chunk, and Mix<b shows <b until the r> arrives. PreviewFeature::HtmlTags (bit 5) removes a trailing fragment that is a strict prefix of one of the five tags, at least < plus one letter or /, as remend requires.
  • Its proof. The same shape as the link proof the pass already has: reparse without the fragment; the block count and every earlier block are unchanged; the last block's text is the previous text minus exactly the fragment; and the fragment was not inside a Code or Math run. A comparison such as a<b mid-stream is hidden for at most one chunk and comes back when the next character proves it is not a tag.
  • Off by default, like every preview feature; preview: true includes it. Never applied once the stream is finished.
  • Committed blocks. Tag state never crosses a block, so the incremental parser's commit boundary and block reuse are unaffected, and the open-fence fast path never sees HTML.

Decisions and risks

The open questions are settled as below. Each is cheap to reverse before release.

QuestionDecisionWhy
Render the three tags by default?decidedYes. inlineHtml defaults to true; inlineHtml={false} restores today's output exactly.It is a contract change, since the contract says raw HTML is "escaped, visible source text". It is what Streamdown shows and what the gap analysis asks for, and a literal <br> in a table is never what a reader wants.
iOS line heightdecidedMeasure in Phase 3. If a line with a script run is more than half a point taller than the same line without one, set maximumLineHeight to minimumLineHeight on paragraphs holding a script or footnote run, except paragraphs with an inline math attachment.Streamdown's lines do not grow, because of Tailwind's line-height: 0. Skipping math paragraphs keeps a tall inline formula from being clipped.
Prop namesdecidedinlineHtml and syntax={{ superscript, subscript }}.enriched's md4cFlags names an implementation, so only its keys are kept. Streamdown's allowedTags means something else: custom tags with attributes.
Android script sizedecided0.75 on both platforms. Split the default only if emulator screenshots visibly differ, through a platform override in ThemeSlots.kt.It matches the footnote reference and keeps a single default in the slot table. enriched uses 0.65 on Android because of Roboto's x-height, which the screenshot check covers.
Announce "superscript" to screen readers?decidedNo. The text is read as written.That is what VoiceOver and TalkBack do with a web <sup>, and announcing every footnote marker would be noise. An accessibility label on the run can add it later.
Soft breaks next to a <br>decidedUse the per-stretch count rule in line break rules.It shows what HTML shows. Someone who writes a⏎<br>⏎b to get a blank line gets none, as they would in Streamdown.
  • Contract change. An app that relied on seeing <br>, <sub> or <sup> as text sees formatting after upgrading. The release notes name inlineHtml={false}.
  • Preview hides a real <b for one chunk. This happens only when the stream pauses exactly there, and only with the opt-in feature on.

Follow-ups this unlocks

All reuse the matcher and existing style bits.

  • More inline tags. <b>/<strong> → Strong, <i>/<em> → Emphasis, <s>/<del>/<strike> → Strikethrough, <code>/<tt>/<samp> → Code. All are in the GitHub schema Streamdown keeps. Each is a table row plus a depth; the raw-html-literal-math fixture would move to a tag not on the list.
  • <kbd> as its own style with a key-cap background, since models write it for shortcuts.
  • <mark> and md4c's ==highlight==, with a highlight.backgroundColor key enriched already has.
  • <details>/<summary> as a collapsible container, which needs a container kind and a toggle, not a style.
